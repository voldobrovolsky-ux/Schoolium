# ADR 0001 — Модульный монолит, не микросервисы

**Статус:** принято · **Дата:** 2026-06

## Контекст
EduStore строится одним фаундером + AI-агентами в сжатые сроки. Нужна
архитектура, которую можно быстро реализовать, но не переделывать через год.
PRD предлагал NestJS modulith + Postgres RLS + NATS + Keycloak + (K8s, ClickHouse,
OpenSearch, OPA, Module Federation, Python ML).

## Решение
Модульный монолит на NestJS с жёсткими границами модулей. Из v1 вырезаны
ops-тяжёлые компоненты (K8s, ClickHouse, OpenSearch, отдельный policy-сервис,
Module Federation, Python ML), добавляются по сигналу нагрузки. Единственный
оправданный отдельный сервис v1 — faster-whisper (другой рантайм).

## Почему
Каждый stateful-сервис — налог, который платит один человек в 2 часа ночи.
Границы доменов ещё не доказаны; modulith позволяет дёшево вынести модуль в
сервис позже. Форма (modulith, RLS, outbox, anti-corruption, roles-as-data)
сохранена — вырезана только распределённая сложность.

## Последствия
+ Быстрый старт, один деплой, общие TS-типы с фронтом.
+ Чёткие границы → дешёвый вынос в сервис при росте.
− Нужна дисциплина границ (eslint-boundaries, отсутствие межмодульных FK-запросов).
− Часть «масштабных» возможностей (федеративная аналитика) откладывается.
