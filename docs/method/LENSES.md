# Реестр линз L-1 … L-18

> **Линза** — переносимый сквозной угол атаки на артефакт. Не раздел спеки и не
> тема: линза светит сквозь **все** разделы и отличается от соседней **классом
> последствия**, а не предметом. Если угол применим только к одному разделу —
> это раздел, а не линза (правила — [LENS-PROTOCOL.md](./LENS-PROTOCOL.md)).
>
> Терминология заимствована у Rozanski & Woods: *view* — что описываем (FSM,
> контракт, экран, данные), *perspective/линза* — качество, которое режет все
> виды сразу. Детектор линзы, доведённый до скрипта, становится
> **фитнес-функцией** в терминах эволюционной архитектуры (Ford/Parsons/Kua) и
> живёт в `docs/G-CHECKS.md`.

**Паспорт линзы** содержит: Вопрос · Последствие · Объект · Детектор · Порог ·
Тип · Стоимость · Держит · Статус. Поле **Детектор** — процедура, дающая
**перечисление**, а не суждение. Линза без детектора допустима только со
статусом `proposed` и только до первой находки.

**Типы** (по Ford): `atomic` (один аспект) / `holistic` (сочетание) ×
`triggered` (по событию) / `continual` (постоянно) × `static` (по документу/коду)
/ `dynamic` (по работающей системе).

## Семейство A — Целостность истины

### L-1 · Источник истины
- **Вопрос:** для каждого факта — одно ли место, где он авторится, и кто побеждает при конфликте записи?
- **Последствие:** расхождение данных, которое нельзя починить кодом — только решением задним числом.
- **Объект:** архитектура · спека · код
- **Детектор:** перечислить все сущности спеки; на каждую — колонки «писатель», «читатели», «что при одновременной записи». Пустая ячейка «писатель» или два писателя без арбитра = находка.
- **Порог:** 0 сущностей с двумя писателями; 0 без арбитра при конкурентной записи.
- **Тип:** atomic / triggered / static
- **Стоимость:** минуты
- **Держит:** AR-2, AR-3, AR-4, AR-12 | G-1, G-12
- **Статус:** active

### L-2 · Полнота FSM
- **Вопрос:** у каждого состояния есть выход, дом на экране и путь к терминалу?
- **Последствие:** пользователь застревает в состоянии, из которого нет выхода; данные зависают в промежуточном виде.
- **Объект:** спека · код
- **Детектор:** матрица `состояние × (выход, дом-экран, терминал, откат)` из `docs/FSM-MATRIX.md`; плюс машинный обход графа переходов на стенде T2 (недостижимые состояния, тупики).
- **Порог:** 100% заполнения; 0 недостижимых; 0 тупиков, кроме явно помеченных терминалов.
- **Тип:** atomic / triggered / static
- **Стоимость:** минуты (матрица) + десятки минут (обход)
- **Держит:** AR-38 | G-8, G-15
- **Статус:** active

### L-3 · Полнота таксономии
- **Вопрос:** каждое enum-значение имеет строку поведения в КАЖДОМ измерении?
- **Последствие:** новое значение (новый тип урока, новый статус документа) молча падает в ветку `default` и ведёт себя как чужое.
- **Объект:** спека · код
- **Детектор:** матрица `значение × измерение` (маршрут, срок, ключ дедупа, резервный путь, календарь, терминал, право доступа). Значение, на которое ссылается поведение, но которого нет в enum, и наоборот — находка.
- **Порог:** 100% ячеек заполнено; 0 висячих ссылок в обе стороны.
- **Тип:** atomic / triggered / static
- **Стоимость:** минуты
- **Держит:** AR-17, AR-25 | G-5
- **Статус:** active

### L-4 · Повтор и идемпотентность
- **Вопрос:** что произойдёт, если это действие/событие придёт дважды, придёт с опозданием, придёт в другом порядке?
- **Последствие:** двойные оценки, двойные списания, каскад, который не останавливается.
- **Объект:** архитектура · код · рантайм
- **Детектор:** перечислить все точки приёма (эндпоинт, подписчик, импорт, ретрай) и на каждой указать ключ дедупа и его срок жизни. Точка без ключа = находка. Прогон: доставить каждое событие дважды на стенде.
- **Порог:** 0 точек приёма без ключа дедупа; повторная доставка не меняет состояние.
- **Тип:** atomic / triggered / dynamic
- **Стоимость:** десятки минут
- **Держит:** AR-5, AR-21, AR-22, AR-24 | G-4, G-5
- **Статус:** active

## Семейство B — Границы

### L-5 · Направление зависимостей
- **Вопрос:** знает ли внутренний слой о внешнем; знает ли модуль о внутренностях соседа?
- **Последствие:** любое изменение инфраструктуры тянет переписывание домена; модуль нельзя вырезать и переписать.
- **Объект:** архитектура · код
- **Детектор:** граф импортов между модулями; список запрещённых рёбер (домен→ORM, модуль→внутренний класс соседа, параметр→FK параметра). Циклы — отдельная находка.
- **Порог:** 0 запрещённых рёбер; 0 циклов между модулями.
- **Тип:** atomic / triggered / static
- **Стоимость:** секунды (скриптом)
- **Держит:** AR-5, AR-8 | G-4
- **Статус:** active

### L-6 · Контракт границы
- **Вопрос:** что именно пересекает границу, кто владеет каждым полем, и что происходит, когда та сторона недоступна или отвечает не так?
- **Последствие:** «кнопка шлёт X, бэк ждёт Y»; отказ внешней системы роняет сценарий целиком.
- **Объект:** спека · код
- **Детектор:** на каждую границу — таблица `поле → владелец → обязательность → поведение при отсутствии`, плюс строка `внешняя система недоступна → что видит пользователь`. Эскалация в скилл `contract-audit`, если граница не описана вовсе.
- **Порог:** 100% границ с описанным отказом; 0 полей без владельца.
- **Тип:** atomic / triggered / static
- **Стоимость:** десятки минут
- **Держит:** AR-1, AR-36, AR-39 | G-14, G-18
- **Статус:** active

### L-7 · Изоляция данных
- **Вопрос:** может ли запрос увидеть данные чужой школы/модуля — чтением, счётчиком, ошибкой или таймингом?
- **Последствие:** утечка между школами. Для B2B-школ — потеря всех школ сразу, не одной.
- **Объект:** код · рантайм
- **Детектор:** перечисление всех моделей с ключом тенанта и всех операций (`find`, `count`, `findUnique`, агрегаты, отчёты); запрос под «не тем» тенантом обязан отдать пусто/отказ. Отдельно — cross-module JOIN.
- **Порог:** 0 моделей вне ключа; 0 cross-module JOIN; аутентифицированный без школы = отказ (fail-closed).
- **Тип:** holistic / triggered / dynamic
- **Стоимость:** минуты (скрипт есть)
- **Держит:** AR-2, AR-34 | G-1, G-11
- **Статус:** active

### L-8 · Владение и разделение обязанностей
- **Вопрос:** у каждого действия один владелец роли, и может ли одна роль пройти весь цикл в одиночку?
- **Последствие:** учитель утверждает сам себе КТП; администратор случайно правит оценки; «система предлагает — человек решает» ломается неявно.
- **Объект:** спека · код
- **Детектор:** обход всех мутаций перечислением; каждая обязана иметь право из каталога либо строку исключения с причиной. Отдельно — матрица `цикл × роль`: есть ли роль, покрывающая все шаги.
- **Порог:** 0 мутаций без гейта; 0 циклов, проходимых одной ролью, кроме явно разрешённых.
- **Тип:** holistic / triggered / dynamic
- **Стоимость:** минуты (скрипт есть)
- **Держит:** AR-16, AR-18, AR-19, AR-35 | G-10
- **Статус:** active

## Семейство C — Изменяемость

### L-9 · Обратимость изменения
- **Вопрос:** как это выключается и как откатывается — включая данные, уже записанные новым кодом?
- **Последствие:** релиз, который нельзя откатить; миграция, ломающая работающий инстанс; фича-флаг, живущий вечно.
- **Объект:** спека · процесс
- **Детектор:** на каждое изменение схемы — план `expand → migrate → contract` с указанием, какая версия кода работает на каждой фазе. На каждый флаг — условие и дата снятия. На каждый заменяемый компонент — план вывода (Strangler Fig) с точкой переключения. **Второй детектор (расширение 2026-08-21, свидетель — аудит обратимости спеки 1.1.1):** перечисление операций продукта парами «действие → обратная операция»; у каждой операции, создающей или меняющей состояние, названа обратная либо записана причина её отсутствия. Первый детектор смотрит на релиз и схему, второй — на то, что человек нажал и не может отменить; дыры второго рода первым детектором не ловятся по построению.
- **Порог:** 0 миграций с downtime; 0 флагов без даты снятия; 0 замен без плана вывода; 0 операций без обратной и без записанной причины.
- **Тип:** atomic / triggered / static
- **Стоимость:** минуты
- **Держит:** AR-4, AR-10, AR-20, AR-85, AR-89, AR-90 | G-12, G-42, G-43
- **Статус:** active

### L-10 · Цена нового элемента
- **Вопрос:** сколько мест надо тронуть, чтобы добавить типовой новый элемент (раздел, роль, тип документа, параметр)?
- **Последствие:** архитектура «затвердевает»: каждая новая школа/модуль стоит дороже предыдущего, и в какой-то момент фича не окупается.
- **Объект:** архитектура · спека
- **Детектор:** прогон сценария-зонда по спеке: «добавляем новый раздел» — перечислить файлы/разделы/таблицы, которые придётся тронуть. Замер, а не мнение. Сравнение с прошлым замером.
- **Порог:** ≤3 точки касания для типового элемента; рост показателя между релизами — находка сам по себе.
- **Тип:** holistic / triggered / static
- **Стоимость:** десятки минут
- **Держит:** AR-8, AR-9 | нет: замер, не инвариант
- **Статус:** active

### L-11 · Наблюдаемость
- **Вопрос:** если это сломается в 8:45 в понедельник у одной школы — как мы узнаем и как найдём причину?
- **Последствие:** инцидент в школе диагностируется по телефону завуча, а не по логам; изменение архитектуры нельзя оценить, потому что нет базовой линии.
- **Объект:** спека · код · рантайм
- **Детектор:** перечислить сценарии спеки; на каждый — `trace-id проходит сквозь все слои?`, `есть событие в логе с обязательными полями?`, `ПД замаскированы?`, `отражается ли отказ в health/readiness?`.
- **Порог:** 100% сценариев с трассировкой; 0 логов с ПД в открытом виде; health отражает состояние зависимостей, а не факт живого порта.
- **Тип:** holistic / continual / dynamic
- **Стоимость:** десятки минут
- **Держит:** AR-21, AR-30 | нет: слот (стандарт логирования)
- **Статус:** active

### L-12 · Деградация
- **Вопрос:** что именно продолжает работать, когда каждая внешняя зависимость по очереди недоступна — и знает ли об этом пользователь?
- **Последствие:** школьный Wi-Fi моргнул — учитель потерял урок оценок и больше не вернулся в продукт.
- **Объект:** спека · код · рантайм
- **Детектор:** перечислить зависимости (Флёрус, S3, ASR, парсер, сеть); на каждую — строка `недоступна → основной сценарий → что видит пользователь → что с данными`. Молчаливый optimistic-апдейт = находка.
- **Порог:** 100% зависимостей с описанной деградацией; 0 молчаливых потерь данных.
- **Тип:** holistic / triggered / dynamic
- **Стоимость:** десятки минут
- **Держит:** AR-12, AR-13, AR-39, AR-40 | G-5, G-7
- **Статус:** active

## Семейство D — Человек и право

### L-13 · Правовой гейт
- **Вопрос:** какая норма касается этих данных/действия, и во что она превращена — в проверку или в абзац текста?
- **Последствие:** штраф, отзыв согласия, запрет на работу с детскими данными. Необратимо и вне инженерного контура.
- **Объект:** спека · код
- **Детектор:** таблица `норма → требование → место в системе → проверка`. Норма без места = находка. Место без проверки = находка. Отдельно: где хранится согласие, что происходит при отзыве, что при удалении.
- **Порог:** 100% норм класса `закон` с местом и проверкой.
- **Тип:** holistic / triggered / static
- **Стоимость:** десятки минут
- **Держит:** AR-6, AR-26, AR-27, AR-28, AR-29, AR-30 | G-2, G-13
- **Статус:** active

### L-14 · Маршрут пользователя
- **Вопрос:** как человек попадает сюда впервые, что видит на пустом месте, и что происходит, если он пришёл не тем путём?
- **Последствие:** продукт куплен школой и не запущен: завуч не смог пригласить учителей, учитель не понял, с чего начать.
- **Объект:** спека · UI
- **Детектор:** перечислить входы (инвайт, QR, ссылка, прямой URL, второе устройство) и для каждого — состояние `первый раз / данных нет / отказ доступа / сессия протухла`. Экран без пустого состояния = находка. Эскалация в скилл `onboarding`.
- **Порог:** 100% входов с описанным пустым состоянием и диагностируемым отказом.
- **Тип:** holistic / triggered / static
- **Стоимость:** десятки минут
- **Держит:** AR-14, AR-15, AR-33 | G-6, G-9
- **Статус:** active

### L-15 · Соответствие UI ↔ бэк
- **Вопрос:** у каждого состояния бэка есть экран, у каждого действия — элемент, и не врёт ли элемент о том, что произойдёт?
- **Последствие:** кнопка «сохранить», которая ничего не сохраняет; состояние, в которое система входит, но которого нет на экране.
- **Объект:** спека · UI · код
- **Детектор:** матрица `состояние бэка × экран` и `действие API × элемент UI × право роли`. Пустая ячейка в любую сторону = находка. Эскалация в скилл `uix-master`.
- **Порог:** 0 состояний без экрана; 0 элементов без права; 0 элементов, доступных роли без права на действие.
- **Тип:** holistic / triggered / static
- **Стоимость:** десятки минут
- **Держит:** AR-35, AR-36, AR-40, AR-41 | G-9, G-14
- **Статус:** active

### L-16 · Нагрузка на человека
- **Вопрос:** сколько действий и минут в день стоит этот сценарий учителю (завучу, родителю) — и на каком месте он бросит?
- **Последствие:** самый частый способ смерти школьного продукта: он работает, но им не пользуются. Не ловится ни одной технической линзой.
- **Объект:** спека · процесс
- **Детектор:** симуляция типового дня на стенде T2: 6 уроков × 25 учеников — посчитать клики/экраны/переключения контекста на массовом действии; отдельно — «холодный старт» (первый месяц: сколько ввода до первой пользы).
- **Порог:** массовое действие (оценка) ≤3 касания с экрана класса; типовой день учителя ≤10 минут ручного ввода; первая польза ≤1 урок после входа.
- **Тип:** holistic / triggered / dynamic
- **Стоимость:** десятки минут
- **Держит:** AR-13, AR-31, AR-42 | нет: замер, не инвариант
- **Статус:** active

## Семейство E — Мета

### L-17 · Свидетельство
- **Вопрос:** каждое «проверено / готово / покрыто» имеет рядом перечисление, а не заявление?
- **Последствие:** ложное чувство покрытия — самая дорогая ошибка метода: она отключает все остальные линзы.
- **Объект:** спека · отчёты · процесс
- **Детектор:** пройти по всем утверждениям готовности в документе; на каждое — ссылка на матрицу, скрипт, прогон или лог. Утверждение без ссылки вычёркивается и записывается как находка.
- **Порог:** 0 утверждений готовности без свидетельства.
- **Тип:** atomic / triggered / static
- **Стоимость:** минуты
- **Держит:** AR-7 | G-10
- **Статус:** active

### L-18 · Дрейф документа
- **Вопрос:** то, на что ссылается спека, ещё существует в коде — и наоборот?
- **Последствие:** документация становится художественной литературой, агент реализует по ней несуществующее.
- **Объект:** спека · код
- **Детектор:** скрипт: имена событий, роутов, прав, таблиц и G-проверок из спеки ищутся в коде; ссылки `AR-N` — в реестрах. Ненайденное = находка. Обратно: новые события/права в коде без строки в спеке = находка.
- **Порог:** 0 висячих ссылок в обе стороны для реализованных разделов.
- **Тип:** atomic / continual / static
- **Стоимость:** секунды (скриптом)
- **Держит:** AR-23, AR-36 | G-16
- **Статус:** active

| «Производительность БД» | Пока нет класса дефекта со свидетелем: нагрузка школы на порядки ниже порога. Живёт как порог в INFRA.md, вернётся линзой при первом инциденте. |
| «Читабельность кода» | Не даёт находок класса «сломается в проде»; закрывается ревью и линтером, не линзой. |
| «Безопасность вообще» | Слишком широкая: разложена на L-7 (изоляция), L-8 (права), L-13 (право/ПД). Единая «линза безопасности» дала бы дубли и нулевую адресность правок. |
