# Параметры: чем измеряется спека и чем измеряется процесс

> Линза отвечает на вопрос «где дыра». Параметр отвечает на вопрос «насколько
> документ готов» — числом, а не ощущением. Параметры спеки (P) проверяются
> линтером на воротах С4; параметры процесса (M) считаются по итогам цикла и
> нужны, чтобы конвейер улучшался, а не просто крутился.

## Часть 1. Параметры спеки (P1…P12)

| ID | Параметр | Определение | Как измеряется | Порог | Ворота |
|---|---|---|---|---|---|
| P1 | Определённость | Плотность размытых формулировок | Словарь размытостей («быстро», «удобно», «оптимально», «и т.д.», «при необходимости», «обычно», «желательно», «по возможности», «корректно», «гибко») на 100 строк | ≤2 / 100 строк; **0** в разделах «Контракт», «FSM», «Права» | линт |
| P2 | Адресность | Доля правил с явным субъектом действия | Мутация/переход без указания «кто» | 0 безадресных | линт |
| P3 | Полнота FSM | Заполненность матрицы `состояние × (выход, дом, терминал, откат)` | Пустая ячейка | 100% | линт + L-2 |
| P4 | Полнота таксономии | Заполненность матрицы `enum-значение × измерение` | Пустая ячейка, висячая ссылка в любую сторону | 100% | линт + L-3 |
| P5 | Разрешимость | Доля ключевых поведений с критерием приёмки в форме «когда … — этап закрыт» | Поведение без критерия | 100% ключевых | линт |
| P6 | Прослеживаемость | Каждое требование имеет вход (`AR-N` / норма / discovery) и выход (`G-n`) | Требование без обеих ссылок | 100% для `[РЕШЕНО]` | линт |
| P7 | Честность маркеров | Отсутствие закрытых утверждений там, где нет основания | Утверждение о готовности без свидетельства; отсутствие `[слот]`/`[узел]`/`[дефолт]` там, где решение не принято | 0 | линт + L-17 |
| P8 | Цена изменения | Точек касания при добавлении типового элемента | Прогон зонда по спеке | ≤3 | L-10 |
| P9 | Дрейф | Доля ссылок спеки, не найденных в коде | Скрипт по именам событий/прав/роутов | 0 для реализованного | L-18 |
| P10 | Отказоустойчивость описания | Доля внешних зависимостей с описанным поведением при недоступности | Зависимость без строки отказа | 100% | L-12 |
| P11 | Правовое покрытие | Доля норм класса `закон` из `10-basis.md`, имеющих место в системе и проверку | Норма без места/проверки | 100% | L-13 |
| P12 | Человеческая цена | Касаний на массовое действие; минут ручного ввода в типовой день | Симуляция на стенде T2 | ≤3 касания; ≤10 мин/день | L-16 |

**Как читается результат.** P1–P7 — машинные, красный = спека не проходит
ворота С4. P8–P12 — замеры, красный = находка в отчёте линз с обязательной
правкой или явным `[узел]`. Спека, зелёная по P1–P7 и не замеренная по P8–P12,
считается **неготовой**: линтер ловит небрежность, а не конструкцию.

**Чего параметры не измеряют** (и это записано сознательно): нужность фичи,
правильность продуктового выбора, качество формулировки на вкус. Идеально
оформленная спека ненужного модуля пройдёт все двенадцать параметров. Это
компенсируется стадиями С1–С2 и discovery, а не линтером.

## Часть 2. Параметры процесса (M1…M6)

Считаются по итогам каждого прогона конвейера, пишутся в `METRICS.md`.

| ID | Метрика | Определение | Что означает рост |
|---|---|---|---|
| M1 | Время цикла | От фразы владельца до зелёной С7 | Рост → конвейер тяжелеет, проверить стоимость линз |
| M2 | Выход с первого прохода | Доля спек, прошедших С4 без возврата | Падение → шаблон/протокол расходится с реальностью задач |
| M3 | Глубина находки | На какой стадии найдена дыра (С5 дешевле С6, С6 дешевле реализации) | Смещение вправо → линзы отстают от стенда |
| M4 | Протечка | Дефектов, найденных **после** сдачи спеки, на спеку | >0 → обязательная заявка на линзу со свидетелем |
| M5 | Реверсы решений | Число `[РЕШЕНО]` → `[узел]`/`[заменено]` за период | Рост → фиксируем преждевременно, статус `[дефолт]` используется недостаточно |
| M6 | Доля вопросов владельцу | Блокирующих вопросов на цикл | Рост → агент не использует реестры; падение до 0 → подозрение на угадывание |

**M6 — двусторонняя метрика.** Ноль вопросов владельцу не является целью:
конвейер, который никогда не спрашивает, либо работает на очень полном реестре,
либо угадывает. Различается по M5: если реверсов много, а вопросов нет — агент
угадывает.

## Часть 3. Порядок замера

1. Линт (P1–P7) — на каждом сохранении спеки и в CI.
2. Замеры (P8–P12) — на стадии С5 (стенд), результат в `40-bench.md`.
3. Метрики процесса (M1–M6) — на С7, строка в `METRICS.md`.
4. Пересмотр порогов — раз в цикл из 5 задач, решением владельца. Порог,
   который ни разу не сработал, ослабляет метод так же, как порог, срабатывающий
   всегда: первый бесполезен, второй игнорируется.
