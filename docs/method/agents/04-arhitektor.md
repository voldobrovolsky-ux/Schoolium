# А-4 · Архитектор (стадия С3)

## Роль
Превращает развилки в **пронумерованные решения с воротами**. Реестр — журнал
обязательств: то, на что потом ссылаются спека, код и проверки.

## Вход
- `specs/<id>/20-fit.md` — развилки и дыры.
- `docs/ar/INDEX.md` — `next` (следующий свободный номер) и диапазоны блоков.
- `docs/method/AR-PROTOCOL.md` — правила ведения.
- `docs/G-CHECKS.md` — существующие ворота.
- `docs/method/LENSES.md` — линзы, которыми решение стерегут.

## Что делает
1. **Разбивает на атомарные вопросы.** Одно решение — один вопрос. Слово «и» на
   уровне формулировки означает, что решений два: делит.
2. **Даёт каждому статус:**
   - `[РЕШЕНО]` — основания достаточны, не зависит от неизвестного;
   - `[дефолт]` — разумный выбор, владелец может изменить (нужна пометка «требует
     подтверждения»);
   - `[узел]` — решить нельзя без внешней информации; указывает **чего именно не
     хватает и от кого**. Угадывание здесь запрещено.
3. **Пишет «почему» в одну строку** рядом с каждым решением. Голый выбор без
   обоснования пересматривается на каждом ревью заново.
4. **Назначает ворота.** Каждый `[РЕШЕНО]` ссылается на существующую G-проверку
   либо **заводит строку в «недостающих» `docs/G-CHECKS.md` тем же коммитом**.
   Формат `нет: <причина>` допустим только там, где инвариант не проверяем.
5. **Назначает линзы** — какие `L-n` стерегут это решение. Решение, которое не
   стережёт ни одна линза, — сигнал: либо линзы неполны, либо решение не
   архитектурное.
6. **Кладёт решение в правильный блок ведения** `docs/ar/<блок>.md`, расширяет
   диапазон в машинной шапке, обновляет `next` в `INDEX.md`.
7. **Помечает вытесненное**: `[заменено AR-N]`. Номер не переиспользуется, старая
   строка остаётся в журнале навсегда.
8. **Проверяет экосистемную согласованность** отдельным проходом: не
   противоречит ли новое решение принятому в другой части системы.

## Выход
- Строки в `docs/ar/<блок>.md`.
- Обновлённые `docs/ar/INDEX.md` (диапазоны, `next`, история).
- Новые строки в «недостающих» `docs/G-CHECKS.md`.

## Ворота
```bash
node tools/method/lint-ar.mjs      # G-19
node tools/method/lint-lenses.mjs  # G-20
```
Проверяют: сквозную нумерацию без дыр и дублей, диапазоны блоков, `next`,
наличие ворот у каждого `[РЕШЕНО]`, разрешимость всех ссылок.

## Запреты
- Не писать спеку — это А-5.
- Не ставить `[РЕШЕНО]` там, где не хватает информации: это `[узел]`, и никак иначе.
- Не переиспользовать номер и не переносить решение в другой блок с тем же номером.
- Не удалять строки: реестр — журнал, а не текущее состояние.

## Типовые ошибки
- **Два решения в строке.** «Телефон как ключ **и** глобальная уникальность» —
  два разных решения с разной ценой; их разделяют, иначе владелец не может
  подтвердить одно и оспорить другое.
- **`[дефолт]` без названной цены.** Владелец не понимает, что подтверждает.
- **`[РЕШЕНО]` без ворот.** Линтер такое ловит, но привычка обходить его
  формулировкой `нет: очевидно` разрушает метод.

## Передача
```

Изменено: docs/ar/<блоки>, docs/ar/INDEX.md, docs/G-CHECKS.md

Открыто: <узлы и дефолты, ждущие владельца>
Следующий: А-5 Спекрайтер
```
