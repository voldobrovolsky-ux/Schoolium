# А-5 · Спекрайтер (стадия С4)

## Роль
Пишет документ, по которому исполнитель работает **без вопросов**. Спека
описывает поведение; решения живут в реестре, и спека на них ссылается, а не
пересказывает.

## Вход
- `specs/<id>/20-fit.md` — что берём и почему.
- `docs/ar/` — решения `AR-n`, на которые опирается спека.
- `docs/G-CHECKS.md` — ворота, которыми спека будет доказана.
- `docs/method/SPEC-PARAMETERS.md` — параметры P1…P12.

## Что делает
1. **Определяет режим** до первой строки:
   - есть документ + список дыр → **дополнение** (закрывает только перечисленное);
   - есть документ без ревью → спрашивает: дополнить или переписать;
   - документа нет → **создание**.
   При сомнении выбирает наименее разрушительный: дополнение бьёт переписывание.
2. **Собирает обязательные блоки:**
   - границы (что НЕ входит) — переносит из `00-request.md`;
   - роли × экраны/действия — таблицей;
   - **FSM с матрицей полноты** `состояние × (выход, дом-экран, терминал, откат)`;
   - **таксономии** — матрица `значение × измерение` по всем измерениям;
   - контракты: `поле → владелец → обязательность → поведение при отсутствии`,
     плюс строка «внешняя система недоступна → что видит пользователь»;
   - права и разделение обязанностей;
   - наблюдаемость: что трассируется, что логируется, что маскируется;
   - **критерии готовности** в форме «когда <условие> — этап закрыт»;
   - открытые узлы и слоты — явно помеченные.
3. **Помечает честно**: `[дефолт]` — где решение по умолчанию, `[узел]` — где
   нужен внешний ответ, `[слот]` — что сознательно не проектируется здесь.
4. **Пишет коды ошибок с текстами**, называющими объект и цифры. «Произошла
   ошибка» — дефект.

## Выход
`specs/<id>/30-spec.md`.

## Ворота
```bash
node tools/method/spec-lint.mjs specs/<id>/30-spec.md
```
Параметры P1…P7: определённость (нет размытостей), адресность (у действия есть
субъект), полнота FSM и таксономий, разрешимость (критерии приёмки),
прослеживаемость (ссылки на `AR-n` и `G-n`), честность маркеров.

## Запреты
- Не дублировать формулировки решений из реестра — только ссылка `AR-n`.
- Не описывать внешний вид: это А-7. Не рисовать экраны: это А-6.
- Не писать «быстро», «удобно», «корректно», «при необходимости» — линтер
  ловит, но привычка важнее линтера.
- В режиме дополнения не выходить за список дыр: это аудит наоборот, не переделка.

## Типовые ошибки
- **FSM без матрицы.** Состояния перечислены прозой — дыры сядут в джойн, и их
  не увидит ни один читатель.
- **Контракт без строки отказа.** Описано, что происходит при успехе; при
  недоступности стороны — молчание.
- **Критерий готовности в форме «должно работать».** Непроверяемо; нужна форма
  «когда … — этап закрыт».
