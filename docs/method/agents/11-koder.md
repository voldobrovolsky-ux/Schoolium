# А-11 · Кодер (вне конвейера спеки)

## Роль
Превращает спеку в работающий продукт. Работает **в отдельном окне**, по
готовому промпту, и начинает не с кода, а с аудита того, что ему дали.

## Вход
Полный промпт — `specs/<id>/80-code-prompt.md`. В нём порядок чтения документов,
этапы и ворота. Здесь — только то, что кодер должен понимать про своё место в
методе.

## Что делает
1. **Этап 0 — генеральный аудит спеки.** Кода не пишет вообще. Семь линий атаки:
   источники истины, полнота FSM, полнота таксономий, контракты, права и
   совмещение ролей, крайние случаи, ложные утверждения. Каждая находка —
   в формате «место → проблема → последствие → решение», с приоритетом.
   Все 🔴 и 🟡 закрываются **правкой спеки**, а не обходом в коде.
   Если правка трогает FSM, генератор или журнал — **сначала обновляется
   исполняемая модель**, она должна падать на старом поведении и проходить на
   новом. К этапу 1 переход запрещён при открытых 🔴.
2. **Этап 1 — контракты и каркас**: схема с ключом тенанта на каждой таблице,
   DTO в общем пакете, события через outbox/inbox, права на каждой мутации.
3. **Этап 2 — десктоп**: все экраны реестра, идентификаторы элементов в
   `data-testid`, три состояния у каждого экрана, только токены — литеральный
   hex запрещён.
4. **Этап 3 — мобайл**: вторая полноценная раскладка, не обрезка адаптивом.
5. **После каждого этапа** сверяется с инвентарём `90-master.md` §3 и отчитывается
   честно: что зелёное, что осталось.

## Выход
Работающий продукт по этапам: правки спеки и модели (этап 0), схема, контракты и
события (этап 1), десктопная реализация всех экранов (этап 2), мобильная
раскладка (этап 3). Плюс отчёт после каждого этапа: что зелёное, что осталось.

## Ворота
Свои на каждом этапе, плюс общие:
```bash
npm run method:lint
node specs/<id>/model/walk.mjs && node specs/<id>/model/props.mjs
```

## Запреты
- Не расходиться со спекой молча: расхождение — сначала правка спеки, потом код.
- Не додумывать элементы: чего нет в реестре экранов — того нет.
- Не «чинить» красный тест подгонкой проверки.
- Не объявлять этап сданным при красных воротах.

## Типовые ошибки
- **Начать с кода.** Этап 0 кажется тратой времени ровно до момента, когда
  находка 🔴 всплывает после трёх дней вёрстки.
- **Работа не на той ветке.** Пакет спеки живёт на ветке-источнике; на основной
  его нет, и там же лежат вытесненные решения. Первое действие — проверить,
  что `specs/<id>/` виден.
- **Литеральные цвета.** Делают проверку контраста декоративной.

## Передача
```
Этап: <0…3>
Изменено: <пути>
Ворота: <команды и статус>
Открыто: <что осталось, честно>
Следующий: <этап или владелец>
```
