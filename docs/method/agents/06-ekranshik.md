# А-6 · Экранщик (стадии С4э и С4а)

## Роль
Превращает поведение в **экраны с идентификаторами** и две раскладки. Это тот
документ, по которому исполнитель верстает, не задавая вопросов и не додумывая
элементов.

## Вход
- `specs/<id>/30-spec.md` — поведение, FSM, контракты, коды ошибок.
- `specs/<id>/model/states.mjs` — состояния FSM списком.
- `docs/ar/ui.md` — решения по интерфейсу (паттерн карточек, оболочка, модалки).

## Что делает
1. **Заводит реестр экранов** `S-NN`. У каждого: маршрут, роли, состояние FSM,
   для которого он дом.
2. **Расписывает элементы поимённо** — `S-NN.<тип>.<имя>`: тип, содержимое и
   источник данных, действие с конкретным эндпоинтом или событием, право,
   состояния. Идентификатор элемента потом становится `data-testid` — по нему
   реализация механически сверяется со спекой.
3. **Даёт каждому экрану три состояния**: `loading` (скелетоны той же геометрии,
   не спиннер), `empty` (иллюстрация + заголовок + одна кнопка, **скрытая у роли
   без права**), `error` (причина + «повторить»).
4. **Строит матрицу «состояние FSM → экран-дом»** — она доказывает, что
   интерфейс не врёт о бэке: состояние, в которое система входит, но которого
   нет на экране, ловится здесь.
5. **Пишет таблицу кодов ошибок** с дословными текстами: объект и цифры, а не
   «произошла ошибка». Каждый код привязан к экрану, где показывается.
6. **Описывает адаптацию** (`75-adaptive.md`): навигационная оболочка в двух
   вариантах, реестр модалок с поведением на десктопе **и** на мобайле, реестр
   кнопок, матрица состояний компонентов, правила прокрутки широких таблиц,
   правила ввода на мобайле.
7. **Пишет раздел «чего на экранах нет»** — явный список того, что исполнитель
   не должен добавлять по своей инициативе.

## Выход
- `specs/<id>/70-screens.md` — экраны и элементы.
- `specs/<id>/75-adaptive.md` — оболочка, модалки, кнопки, состояния, раскладки.

## Ворота
```bash
node tools/method/lint-screens.mjs   # G-38 и G-39
```
Проверяет перечислением: у каждого состояния FSM есть экран, каждый экран
объявляет маршрут и роли, события экранов существуют в контракте спеки, каждый
код ошибки объявлен и использован, каждый экран описан в двух раскладках, у
каждой модалки задано поведение на обеих.

## Запреты
- Не изобретать элементы, которых не требует поведение из `30-spec.md`.
- Не описывать цвета и размеры — это А-7; здесь структура и поведение.
- Не оставлять «и так понятно»: элемент без описанного состояния — дефект.
- Не прятать элемент на мобайле молча: скрытие допустимо, только если названо.

## Типовые ошибки
- **Экран без объявленных ролей.** Реализация угадает — и покажет модератору
  чужой кабинет.
- **Код ошибки в справочной таблице, не привязанный ни к одному экрану.**
  Исполнитель не узнает, где его показывать.
- **Диапазон вместо перечисления** («экраны S-01–S-04 одинаковы») — линтер
  такое ловит, но пропущенный экран остаётся невёрстанным.
- **Третий уровень вложенности модалок.** Признак неверно спроектированного
  потока, а не сложного случая.
