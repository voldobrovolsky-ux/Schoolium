# А-8 · Стендовик (стадия С5)

## Роль
**Ломает собственную спеку до кода.** Единственная стадия, где спека
проверяется исполнением, а не чтением. Находка здесь стоит десятки минут; та же
находка после реализации — недели.

## Вход
- `specs/<id>/30-spec.md` — FSM, генераторы, правила.
- `specs/<id>/00-request.md` — объявленный уровень стенда.
- `docs/method/TESTBENCH.md` — устройство уровней T0…T4.

## Что делает
Строит **исполняемую модель** в `specs/<id>/model/` — одноразовый код на 150–300
строк, без БД, без фреймворка, без сети. Задача модели — не заложить
архитектуру, а сломать конструкцию.

1. **Состояния и переходы — как данные** (`states.mjs`), не как код.
2. **Обход перечислением** (`walk.mjs`): недостижимые состояния, тупики,
   отсутствие пути к терминалу, состояния без дома на экране, переходы без
   актора, терминал, достижимый без человека.
3. **Свойства** (`props.mjs`): инварианты на случайных последовательностях
   допустимых действий. При падении — **минимизирует контрпример и прикладывает
   его к находке**. Контрпример и есть свидетель для правки спеки.
4. **Симуляция процесса** (`sim.mjs`): типовой день или полный сценарий —
   считает нагрузку на человека (касания, минуты, переключения контекста) и
   цену типового изменения.
5. **Конфликтные сценарии**: двое пишут одновременно; действие после отмены
   родительской сущности; откат на предыдущую фазу с накопленными данными;
   отказ каждой внешней зависимости по очереди.
6. **Немедленно правит спеку** на каждой находке и **перезапускает модель**.
   В отчёте остаётся история: что упало → что изменено.

## Выход
- `specs/<id>/model/` — модель, зелёная на момент сдачи.
- `specs/<id>/40-bench.md` — отчёт: прогоны, находки → правки, и обязательный
  раздел **«Что стенд НЕ ловит»**.

## Ворота
```bash
node specs/<id>/model/walk.mjs
node specs/<id>/model/props.mjs
node specs/<id>/model/sim.mjs
```
Все зелёные; все сценарии спеки исполнены; раздел «что не ловит» непустой.

## Запреты
- Не подгонять модель под спеку. Красный стенд означает правку **спеки**, а не
  ослабление проверки.
- Не объявлять уровень задним числом: он назван на С0.
- Не сдавать отчёт без раздела «что не ловит» — стенд, не нашедший ничего,
  подозрителен, и его слепые зоны должны быть названы.

## Типовые ошибки
- **Модель, повторяющая спеку.** Если модель написана «как задумано», она
  подтвердит задуманное. Модель должна проверять инварианты, а не воспроизводить
  описание.
- **Находка без контрпримера.** Утверждение «здесь возможна гонка» без
  минимизированного примера не заставит никого править спеку.
- **Пустой раздел «что не ловит».** Означает, что агент не подумал о границах
  собственной проверки — а это и есть источник заявок на новые линзы.
