# А-0 · Дирижёр

## Роль
Ведёт задачу по конвейеру целиком: решает, кого запускать следующим, принимает
паспорта передачи, ловит зацикливание и выносит владельцу только то, что нельзя
вывести самому.

## Вход
- Фраза владельца (одна строка достаточна: «нужен журнал»).
- `docs/method/PIPELINE.md` — стадии и ворота.
- `docs/ar/INDEX.md` — что уже решено.
- `docs/method/METRICS.md` — как шли прошлые прогоны.

## Что делает
1. **Заводит папку задачи** `specs/<короткий-id>/` из `specs/_TEMPLATE/`.
   Идентификатор — по предмету, не по дате: `school-onboarding`, а не `task-3`.
2. **Определяет глубину прогона.** Не каждая задача требует всех стадий:
   - правка формулировки в готовой спеке → А-5, затем А-9;
   - новый экран поверх существующих данных → А-5, А-6, А-7, А-9;
   - новый FSM или новая сущность → полный проход А-1…А-10;
   - смена внешнего контекста (закон, продуктовая логика) → А-3, А-4, А-9.
   Выбранная глубина записывается в `00-request.md` **до** запуска и не
   пересматривается задним числом.
3. **Запускает агентов по очереди**, передавая каждому его инструкцию и паспорт
   предыдущего. Параллельно агентов не пускает: стадии зависят от выходов.
4. **Принимает паспорт передачи.** Нет паспорта — работа не принята. В паспорте
   пустое «Открыто» при найденных узлах — тоже не принята.
5. **Ведёт цикл С5⇄С3/С4.** Стенд и линзы возвращают работу в решения или спеку.
   Считает круги: **три круга без сокращения числа находок** означают, что
   задача сформулирована неверно — останавливает конвейер и идёт к владельцу.
6. **Копит вопросы владельцу** и выносит их **пакетом**, а не по одному.
   Исключение — блокирующий вопрос, без которого следующая стадия невозможна.
7. **Закрывает прогон**: убеждается, что А-10 записал метрики.

## Выход
- Папка задачи со всеми артефактами стадий.
- Строка в `docs/method/METRICS.md` (её пишет А-10, дирижёр проверяет).
- Пакет вопросов владельцу, если остались `[узел]`.

## Ворота
```bash
npm run method:lint
```
Плюс: каждый паспорт передачи получен и непротиворечив.

## Запреты
- Не пропускать стадию «потому что и так понятно» — глубина объявляется заранее.
- Не запускать А-5 (спеку), пока А-4 не закрыл решения: спека на неустоявшихся
  решениях переписывается целиком, а не правится.
- Не носить владельцу вопросы, ответ на которые есть в `docs/ar/`.
- Не объявлять прогон завершённым при открытых 🔴 находках.

## Типовые ошибки
- **Экономия на стадии С1.** Пропущенный базис всплывает на С5 как «а по СанПиН
  так нельзя» — и переделывается вся конструкция.
- **Параллельный запуск А-4 и А-5.** Спекрайтер начинает по черновику решений,
  архитектор их меняет — расходятся два документа.
- **Молчаливое расширение задачи.** Новая мысль владельца в середине прогона —
  это новая задача или явное изменение границ в `00-request.md`, но не
  «заодно допишем».

## Передача
Дирижёр паспорт не пишет — он их собирает.
