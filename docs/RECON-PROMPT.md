# Промпт для новой сессии: рекогносцировка пакета 1.3.0

Скопируй текст ниже в новую сессию Claude Code (репозитории `Schoolium` и
`flor-platform-docs` подключены). Промпт не просит новых функций — только
проверку того, что сделано, и разбор найденного.

---

Ты проводишь рекогносцировку пакета Schoolium 1.3.0 (ветка
`claude/schoolium-admin-cabinet-ui-rntrn6`, документ пакета —
`docs/CHANGES-2026-09-02.md`). Новых функций не пишем: цель — убедиться, что
приложение готово к эксплуатации в первой версии, и составить список дефектов
с приоритетами. Правила репозитория: `CLAUDE.md`, `docs/PROD-STATUS.md`
(прод-сервер с реальными данными — ничего разрушающего), семь правил
`flor-platform-docs/CLAUDE.md` §1 (не угадывать, «работает» только со ссылкой
на зелёную проверку).

Сделай по порядку и фиксируй результат каждого шага в отчёте
`docs/RECON-2026-09-XX.md` (дата сессии):

1. **Состояние CI.** Найди последний прогон CI по ветке пакета (GitHub Actions,
   workflow `CI`): все четыре джоба зелёные? Если нет — выпиши падающий шаг и
   первые строки причины, не чини молча.
2. **Ворота локально.** Подними Postgres, `npm install`, `npx prisma migrate
   deploy`, затем `npm run method:lint`, `npm --workspace apps/api run
   schoolium:check`, `npm --workspace apps/web run smoke:onboarding` и
   `smoke:onboarding:mobile`. Сравни числа проверок с `docs/G-CHECKS.md`
   (G-81 — 67, G-41 — 34, G-50 — 87). Расхождение — находка.
3. **Три кабинета глазами ролей.** Через `apps/api/scripts/school-bootstrap.ts`
   и `school-provision.ts` заведи стенд с администратором, модератором и
   завучем (три ссылки на 48 часов). Пройди каждым: администратор —
   `/admin` (обзор, устройства, роли, сеть, аудит, политики; выдай ссылку входа
   с карточки `S-31`, заверши чужую сессию, включи и посмотри инцидент-режим);
   модератор — `/moderator` и отказ на `/admin`; завуч — `/deputy`, чек-листы,
   нормы часов на `/schedule`, отказ на `/moderator`. Скриншоты — в отчёт.
   Сверяй с `docs/CABINETS.md`: любое расхождение матрицы и экрана — дефект.
4. **Телефон.** В раскладке 390×844 проверь: экран входа по коду (ячейки в
   карточке), меню пользователя с кабинетами, `S-81` установка приложения
   (Android-ветка и iPhone-ветка), карта устройств в одну колонку без
   горизонтального скролла `body`.
5. **Сеть и устройства.** Войди одним пользователем с двух «устройств» (два
   контекста браузера), подключи второе сканом QR со страницы входа — на карте
   администратора второе устройство должно быть вложено под телефон, прямой
   вход — под человека. Поставь лимит сессий 1 для роли и войди второй раз —
   первая сессия должна закрыться с причиной «лимит сессий» в журнале.
6. **Документация.** Прочитай `docs/CABINETS.md`, `docs/CHECKLIST-UTC-KPC.md`,
   AR-186…AR-194 и сверь с кодом (права в `packages/shared`, маршруты в
   `apps/api/src/schoolium/cabinets`). Утверждение без свидетельства — дефект
   документации.
7. **Аудит в экосистеме.** Открой
   `flor-platform-docs/audits/2026-09-02-schoolium-1.3.0.md`: для каждого
   пункта «остаток» проверь, актуален ли он; закрытые пометь датой и ссылкой
   на проверку, новые добавь.

Отчёт заканчивается таблицей дефектов: приоритет (блокирует эксплуатацию /
мешает / полировка), где (экран или файл), как воспроизвести, чем доказано.
Не предлагай новых разделов и функций — только дефекты и недостающие
проверки.
