# Пакет 1.5.0 — что изменилось и почему

Одна сессия, шесть пунктов владельца и завуча (созвон 2026-09-03), один пакет.
Документ — **реестр правок**: что сделано, каким решением закреплено, какими
воротами доказано, что осталось узлом. Решения — `docs/ar/*.md` (AR-199…AR-210),
ворота — `docs/G-CHECKS.md`, экраны — `specs/school-onboarding/70-screens.md`.

## 1. Как читать изменения по слоям

### Контракт (`packages/shared/src/schoolium.ts`)
- Права: `schedule.preference.self`, `lesson.cancel.self` — пакет `teacher`.
- Коды отказа: `SUBJECT_EXISTS`, `GROUPS_BOUND`, `ROLE_LIMIT_REACHED`,
  `LINK_EXHAUSTED`, `TEACHER_DAYS_SHORT`, `NOT_YOUR_LESSON`,
  `LESSON_ALREADY_HELD`, `LESSON_CANCELLED`, `SUBSTITUTE_BUSY`; три кода
  СанПиН выведены из употребления; `ARITHMETIC_REFUSALS` — шесть.
- Функции: `subjectNameKey`, `canonicalSubjectName`, `effectiveRoleLimit`
  с `DEFAULT_ROLE_LIMITS`; словари `LESSON_CANCEL_REASONS`,
  `ACCESS_PARAMS.loginLinkTtlOptions/loginLinkUsesOptions`.
- DTO: обед класса, группы класса, учётка и пароль сотрудника, ссылка входа с
  параметрами, политика с `roleLimits`/`roleHolders`, предпочтения педагога,
  датированные уроки с заменой, отмена/назначение замены, дневник с
  `cancelled`/`substituteName`.

### База (`apps/api/prisma`)
Одна миграция `20260904090000_deputy_pack_0409`, только расширение:
`SchoolClass.lunchAfterLessonNo`, `SchoolSubject.nameKey` (с бэкфиллом и
обычным индексом — уникальный индекс добавится после слияния дублей на
проде), `BootstrapLink.maxUses/useCount`, `SchoolAccessPolicy.roleLimits`,
`JournalColumn.cancelledAt`, таблицы `TeacherPreference` и `LessonSubstitution`
под tenant-guard. Откат на прежний тег остаётся возможным: старый код лишних
колонок не читает. Применяет контейнер API при старте.

### События (`apps/api/src/schoolium/schoolium.contract.ts`)
32 события (было 25): `schedule.lesson.cancelled.v1`,
`schedule.lesson.reassigned.v1`, `schedule.lesson.restored.v1`,
`schedule.preference.set.v1`, `staff.account.updated.v1`,
`staff.password.set.v1`, `contingent.class.regrouped.v1`; у каждого —
издатель, подписчик, реакция и подпись аудита; `school.policy.set.v1` несёт
`roleLimits`, `staff.login_link.issued.v1` — срок и лимит открытий.

### API (`apps/api/src/schoolium`)
- Расписание: `PUT /schedule/lunch`, `GET/PUT /schedule/preferences/me`,
  `GET /schedule/preferences`, `GET /schedule/lessons?from&to`; генератор без
  норм СанПиН, с обедом класса и рабочими днями педагога.
- Уроки: `POST/DELETE /lessons/:id/cancel`, `POST /lessons/:id/substitute`
  (`SubstitutionService`); журнал переставляет педагога колонки по событию и

- Предметы: ключ имени, `SUBJECT_EXISTS`, компетенции с группами,
  `PUT /classes/:id/groups`; скрипт `school-subjects-merge.ts`.
- Персонал: `PUT /staff/:id/account`, `POST /staff/:id/password`, ссылка
  входа с параметрами под `staff.manage`; лимиты носителей ролей в
  `addCard`/`addRole`/`reactivate`; политика с `roleLimits`.

## 2. Узлы владельца (не угадано)

- **AR-209** — допускать ли замену педагогом другой дисциплины (присмотр),
  когда педагога того же предмета в слоте нет. Пока — урок отменяется и
  показывается «Уроков без замены».
- **AR-210** — нужно ли собственное разбиение учеников по предмету, отличное
  от групп класса. Пока — группы класса (AR-75).
- Слияние дублей на проде выполняется только после dry-run по логу прогона
  workflow; Д6-конфликты между дублями не сливаются автоматически.

## 3. Чего в пакете нет и почему

- Уникальный индекс по ключу имени предмета — второй миграцией после
  слияния прода (миграция с уникальностью упала бы на несведённых дублях, а
  применяет её контейнер API при старте).
- Разные времена уроков у ступеней (полный скелет на ступень) — остаётся
  слотом AR-171; обед по классам сделан на общей сетке.
- Долг часов и добор (AR-145) — слот блока «Расписание»; отмена урока без
  замены час не добирает.
- Утверждение предпочтений директором (AR-135) — не делается: рабочие дни
  педагог задаёт сам.
