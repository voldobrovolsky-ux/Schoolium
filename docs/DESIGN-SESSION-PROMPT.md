# Промпт для новой сессии: дизайн Schoolium на библиотеке компонентов

Скопируй текст ниже в новую сессию Claude Code (репозитории `Schoolium` и
`flor-platform-docs` подключены). Ветка `main`, релиз 1.3.0 + правки 03.09.

---

Ты делаешь пакет «Дизайн 1.4.0» для Schoolium: интерфейс сейчас выглядит как
сгенерированный ИИ (самописные кнопки, карточки, модалки, бейджи в
`apps/web/src/schoolium/ui.tsx` и `app.css`), владелец требует
профессиональный вид на **готовой библиотеке компонентов**. Правила:
`CLAUDE.md`, `docs/PROD-STATUS.md` (прод с реальными данными — деплой только
workflow `deploy-school`, ветка `main`), семь правил
`flor-platform-docs/CLAUDE.md` §1. Никаких новых функций — только внешний
вид, поведение экранов и идентификаторы не меняются.

Сделай по порядку, результат каждого шага — коммит в `main` через PR.

1. **Выбор библиотеки — новое архитектурное решение.** Сравни три варианта на реальном
   стеке (React 18 + Vite, TypeScript, CSS-токены `docs/design/tokens.json`,
   без Tailwind): (а) `@radix-ui/themes`; (б) Radix Primitives + shadcn/ui
   (требует Tailwind); (в) Radix Primitives + собственные стили на токенах.
   Критерии: доступность из коробки (фокус, клавиатура, aria), модалки и
   поповеры с фокус-ловушкой, мобильные листы, размер бандла, совместимость
   с воротами G-37 (цвета только из токенов, 74 CSS-переменные) и G-83
   (иконки только `lucide` через `Icon`). Запиши решение в
   `docs/ar/ui.md` (номер из `docs/ar/INDEX.md` → `next`), с ценой и
   воротами. Не угадывай — проверь установкой и сборкой.
2. **Дизайн-система.** Шкала типографики (Inter/Manrope уже подключены),
   шкала отступов 4/8/12/16/24/32, радиусы, тени, три тона кнопок
   (primary/secondary/ghost/danger), состояния hover/active/disabled/loading,
   поля ввода с ошибками, бейджи, плитки статистики, карточки. Всё — в
   `tokens.json` и `tokens.css`, `node tools/design/tokens-to-css.mjs --check`
   зелёный. Эталон — Linear, Notion, Stripe Dashboard: плотно, спокойно,
   без градиентных плашек и «подпрыгивающих» карточек.
3. **Замена компонентов `ui.tsx` по одному**, сохраняя `testId` и
   `data-testid` каждого элемента (реестр `specs/school-onboarding/70-screens.md`,
   проверка `node tools/method/check-testids.mjs`): Button, Input, Select,
   Modal/PopoverOrSheet (Radix Dialog/Popover), Badge, Stat, SubNav, Toast,
   Skeletons, EmptyState, Avatar, CopyField. Экраны не переписывать —
   они используют эти компоненты.
4. **Оболочка** (`shell.tsx`): сайдбар десктопа, хедер и таб-бар телефона,
   меню пользователя `M-15`. Логотип — только «Schoolium».
5. **Карточка сотрудника `S-31`/`M-06`** (`screens/staff.tsx`): одна
   раскладка группами для активированной и не активированной учётки
   (сделано 03.09), привести к новой системе: QR активации, код входа,
   ссылка входа, активность, профиль, доступ.
6. **Три кабинета** (`admin.tsx`, `deputy.tsx`, `misc.tsx` S-60), журнал,
   расписание, классы, предметы, персонал, настройки — пройти каждый экран
   на 1440×900 и 390×844, скриншот до/после в `docs/design/1.4.0/`.
7. **Ворота.** `npm run method:lint`, `npm --workspace apps/web run
   smoke:onboarding` и `smoke:onboarding:mobile` (в агентной среде нужен
   `CHROMIUM_PATH=/opt/pw-browsers/chromium-1194/chrome-linux/chrome`),
   `npm --workspace apps/api run schoolium:check` — все зелёные перед каждым
   PR. «Работает» — только со ссылкой на зелёный прогон.
8. **Деплой** с `main` workflow `deploy-school` `action=deploy`, проверка на
   телефоне владельца: второе открытие или `?v=N` сбрасывает прошлую оболочку.

Отчёт в конце: что заменено, что осталось самописным и почему, размер
бандла до/после, ссылки на зелёные прогоны, скриншоты до/после.
