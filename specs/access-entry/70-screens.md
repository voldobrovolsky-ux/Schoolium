## S-00 · Лендинг (правка: лента школ)

- **Маршрут:** `/` · **Роли:** аноним (с сессией → стартовый экран роли)

| Элемент | Тип | Содержимое / источник | Действие | Состояния |
|---|---|---|---|---|
| `S-00.logo`, `S-00.hero` | без изменений | «премиальный минимум» сохраняется | — | — |
| `S-00.btn.login` | primary, pill | «Войти» | аноним → плавный скролл к `S-00.schools`; с сессией → стартовый экран роли | — |
| `S-00.schools` | лента-карусель | `GET /v1/schools` (4 поля, AR-163) | автопрокрутка слева направо; **< 5 школ — статичный ряд без анимации** (У-12); `prefers-reduced-motion` — всегда статично | loading (скелетон) / empty (лента скрыта, `btn.login` → `/login`) / error (лента скрыта) |
| `S-00.school-card` | карточка | аватар/инициалы · название · «N участников» | → `/schools/:id` (`S-93`) | hover-подъём; пауза прокрутки при hover |

- **mobile:** лента горизонтальным свайпом, автопрокрутка выключена.
- **M-21 не вызывается и удаляется** вместе со своей секцией реестра (AR-167).

## S-93 · Экран школы (новый)

- **Маршрут:** `/schools/:id` · **Роли:** аноним (с сессией → стартовый экран роли)
- **Источник:** `GET /v1/schools/:id` — ровно `id`, `name`, `logoUrl`,
  `memberCount` (контракт AR-163; новый эндпоинт).

| Элемент | Тип | Содержимое / источник | Действие | Состояния |
|---|---|---|---|---|
| `S-93.head` | шапка | аватар/инициалы + название + «N участников» | — | — |
| `S-93.qr` | QR 240px | токен привязки устройства — та же механика, что `S-01.qr` (TTL 3 мин, поллинг 2 с, автоперевыпуск) | сканирует телефон с активным кабинетом | активен / истёк (авто-перевыпуск) |
| `S-93.tab.mode` | переключатель | «QR» ⇄ «По коду» ⇄ «Юзернейм и пароль» | меняет содержимое блока входа | qr / code / password |
| `S-93.code` | 6 окошек | режим «По коду»: код от модератора **этой школы** | автоотправка по последней цифре: `POST /v1/auth/login-code/verify {code, schoolId}` (AR-166) | ввод / ошибка (встряска + очистка) |
| `S-93.input.username`, `S-93.input.password`, `S-93.btn.submit` | форма | режим «Юзернейм и пароль» | `POST /v1/auth/login {username, password, schoolId}`: членство проверяется **в этой школе**, отказ всегда `LOGIN_FAILED` (AR-167/AR-154) | ввод / ошибка |

- **error:** `LOGIN_CODE_INVALID` — «Код не подходит. Код действует 5 минут и
  только в своей школе» (код чужой школы неотличим от неверного);
  `LOGIN_FAILED` — единый текст; `ACCESS_REVOKED` — как на `S-01`.
- **Школа не найдена / неактивна:** экран-заглушка «Школа не найдена» +
  ссылка на `/schools`.
- **mobile:** дефолтный режим — `code` (телефон не сканирует сам себя);
  **desktop:** дефолт `qr` (целевой п.5 — «по дефолту рендерится QR»).

## S-05 · Ввод кода (правка: только в контексте школы)

- **Маршрут:** был `/login/code` — становится **`/schools/:id/code`**; глобальные
  `/login/code` и `/login/code/:code` выводятся (AR-166). QR-представление кода
  меняет значение: было `origin/login/code/<цифры>` — становится
  `origin/schools/<schoolId>/code/<цифры>` (школа зашита в ссылку, скоуп
  сохраняется и при сканировании).
- Остальное содержимое секции S-05 (ячейки, сканер, fallback камеры) — без
  изменений, но `verify` всегда несёт `schoolId`.

## S-03 / `/join/:token` · Активация по ссылке (правка: отказы и гейт)

Механика активации без изменений (AR-161). Меняются исходы (AR-165, AR-170):

| Состояние | Экран | Действие |
|---|---|---|
| Ссылка истекла (`TOKEN_EXPIRED`) | «Ссылка истекла — она живёт 15 минут» | «Попросите модератора школы выпустить новую (ваша карточка → QR)»; для платформенной ссылки — «запросите новую у выпустившего» |
| Ссылка уже использована (`TOKEN_USED`), **своя** живая сессия есть | «Вы уже вошли» | кнопка «Перейти в кабинет» (стартовый экран роли) — вместо нынешнего тупикового текста |

| Устройство занято **чужой валидной** сессией (гейт AR-91) | «На этом устройстве открыт другой кабинет» | кнопка «Выйти и продолжить вход» (логаут текущей сессии → повтор активации); гейт срабатывает **до** гашения токена (Б-3) |

- Cookie, выданная активацией, — httpOnly **90 дней**, как у всех каналов (Б-1).

## S-80 · Устройства (правка)

- `S-80.confirm` называет устройство: «Подключить **Chrome · Windows**?» —
  `DeviceLinkToken` получает поле `deviceHint` (UA ожидающего устройства,
  пишется при выпуске токена); `deviceHint` создаваемой **сессии** — тоже от
  ожидающего устройства, не от телефона-сканера (сейчас в списке ноутбук
  называется браузером телефона).
- Статус-эндпоинт отдаёт сессию **один раз** (Б-6): повторный опрос после
  выдачи — `TOKEN_USED`.
- Desktop-якорь: вместо `window.prompt` на 48-hex — поле вставки ссылки
  (вторично; телефон остаётся основным якорем).

## S-31 / S-13 / S-14 · Карточки (правка)

- Рядом с активационным QR появляется `*.btn.url` — та же кнопка «URL», что в

- Панель «Код для входа» (QR + цифры) появляется у ученика (`S-13`) и родителя
  (`S-14`): `POST /v1/students/:id/login-code`, `POST /v1/guardians/:id/login-code`

- Обещанный реестром таймер обратного отсчёта на панели кода — реализуется
  (долг спека↔код закрывается этим инкрементом).

## Консольный канал (без экрана — по прецеденту AR-93)

```bash
npm run user:create -- --workspace=<id> --role=teacher|student|guardian|admin \
  --last="Фамилия" --first="Имя" [--middle="Отчество"] \
  [--username=...] [--password=...] [--class=<id>]   # --class обязателен для student
```

- Создаёт учётку + карточку-носителя (AR-164), печатает юзернейм и **однократно**
  ссылку на кабинет (15 мин, AR-165); пароль — только с флагом `--show-password`.
- Workflow-action `user-create` (быстрый, без деплоя): те же входы; ссылка
  печатается в лог прогона (названная цена У-11).
