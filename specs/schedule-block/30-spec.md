## 2. Как машина считает (AR-118)

> Задача блока одной фразой: **выстроить предметы комфортно и логично.** Ниже —
> как это считается. Словарь, переводящий термины этого раздела на язык, которым
> система говорит с человеком, — в [`35-parameters.md`](./35-parameters.md),
> раздел «Словарь»: на экранах слов этого раздела нет (AR-143, ворота G-62).

### 2.1 Множества и переменная

| Объект | Обозначение | Определение |
|---|---|---|
| Дни недели | `D` | `{0…d−1}`, `d ∈ {5, 6}` — параметр `days` |
| Позиции дня | `P` | `{1…p}`, `p` — параметр `slotsPerDay` |
| Слоты недели | `S = D × P` | `|S| = d·p` |
| Классы | `C` | у класса `c` есть параллель `par(c)` и число групп `γ(c)` |
| Педагоги | `T` | множество активных сотрудников с ролью преподавателя |
| Предметы | `J` | карточка предмета версии 1.1.1 — пара «предмет × класс» |
| Нагрузка | `L ⊂ J × C × T × {class, group} × 2^Γ × ℕ` | ввод экрана `S-41` шаг 2 |

**Единица планирования** `u ∈ U` — неделимый объект, занимающий ровно один слот.
Пара нагрузки `(j, c, t, class, ∅, h)` порождает `h` единиц с одной частью. Все
пары `(j, c, ·, group, ·, h)` одного предмета порождают `h` единиц, у каждой по
части на группу: групповой час неделим (AR-75). Отсюда `|U| = Σ_c H_c`, где
`H_c` — недельные часы класса, а часы групп одного предмета входят в `H_c`
однократно, потому что группы занимают один слот параллельно.

**Переменная модели** — полное присваивание `x: U → S`. Расписание есть `x`;
всё остальное (шаблон, слоты, уроки) — его проекции.

### 2.2 Жёсткие ограничения (допустимость)

Сетка `x` допустима, когда выполнены все семь. Обозначим `cap(c) = min(p, σ(par(c)))`,
где `σ` — дневной потолок параллели из СанПиН 1.2.3685-21 табл. 6.6 (базис #11).

| № | Ограничение | Формально |
|---|---|---|
| H1 | Нагрузка выполнена полностью | `x` определено на всём `U`, инъекций сверх `U` нет |
| H2 | Педагог не в двух местах | `∀ s ∈ S, ∀ t ∈ T: |{u : x(u)=s, t ∈ teach(u)}| ≤ 1` |
| H3 | Класс не в двух местах | `∀ s ∈ S, ∀ c ∈ C: |{u : x(u)=s, cls(u)=c}| ≤ 1` |
| H4 | Групповой час атомарен | части единицы `u` неразделимы: у них общее значение `x(u)` |
| H5 | У класса нет окон | `∀ c, ∀ δ ∈ D: {π : x(u)=(δ,π), cls(u)=c} = {1…k}` для некоего `k ≥ 0` |
| H6 | Дневной потолок параллели | тот же `k ≤ cap(c)` |
| H7 | Длина дня в границах | `p·ℓ + (p−1−β)·b + β·B ≤ 420` мин, где `β = 1` при заданной большой перемене |

H4 в реализации структурен: единица — одна запись, её части не имеют
собственных координат. H7 от `x` не зависит вовсе — это ограничение на
параметры, и потому движок считает его до построения сетки.

### 2.3 Необходимые условия непустоты (леммы, AR-118)

Восемь арифметических отказов версии 1.1.1 — не эвристики, а леммы о том, что
множество допустимых сеток пусто. Каждая доказывается принципом Дирихле, и
потому движок считает их до перебора: перебор арифметику опровергнуть не может.

| Лемма | Утверждение | Код отказа |
|---|---|---|
| Л1 | `H_c > W(par(c))` ⟹ допустимых сеток нет (недельный потолок СанПиН) | `LOAD_EXCEEDS_SANPIN` |
| Л2 | `H_c > d·cap(c)` ⟹ по H5+H6 класс не вмещает свои часы | `LOAD_EXCEEDS_GRID` |
| Л3 | `Σ_j h(t,j) > d·p` ⟹ по H2 педагог не вмещает свои часы | `TEACHER_OVERBOOKED` |
| Л4 | часы групп одного предмета не равны ⟹ по H4 единица непостроима | `GROUP_HOURS_UNEQUAL` |
| Л5 | у предмета нет педагога на группу ⟹ единица непостроима | `SUBJECT_UNCOVERED` |
| Л6 | группы объявлены, состав не назначен ⟹ единица планирует пустоту | `GROUPS_UNASSIGNED` |
| Л7 | `p > max_c σ(par(c))` ⟹ H6 нарушено у старшей параллели (AR-114) | `DAY_EXCEEDS_SANPIN` |
| Л8 | длина дня выше 420 мин ⟹ H7 нарушено параметрами | `DAY_TOO_LONG` |

Условия Л1…Л8 **необходимы, но не достаточны**: их выполнение не влечёт
существования допустимой сетки. Свидетельство — фрагментация расписания
педагога, делящего часы между классами с разными потолками дня: суммы сходятся,
расстановка не существует. Поэтому девятый код `NO_SOLUTION` принадлежит
перебору и остаётся единственным его отказом (AR-107).

### 2.4 Сложность и следствие для конструкции

Задача построения `x` при H1…H6 содержит как частный случай раскраску
двудольного мультиграфа «класс × педагог» с ограничением на кратность цвета,
то есть класс задач, для которого не известно алгоритма полиномиальной
сложности. Отсюда три конструктивных следствия, а не одно:

1. Перебор ограничен названным бюджетом (AR-107), исчерпание — честный
   `NO_SOLUTION`, а не бесконечное ожидание.
2. Первая найденная допустимая сетка не является наилучшей ни в каком смысле —
   значит, нужна мера, по которой сетки сравнимы (§3).
3. Улучшение идёт локальным поиском по уже допустимой сетке (§5), а не вторым
   заходом перебора: перебор не умеет улучшать, он умеет находить.

### 2.5 Целевая функция

На множестве допустимых сеток задан **целочисленный штраф**

```
Π(x) = Σᵢ wᵢ · πᵢ(x),   wᵢ ∈ ℕ,   πᵢ(x) ∈ ℤ≥0
```

Наилучшая сетка — минимизирующая `Π`. Целость `πᵢ` и `wᵢ` — требование
конструкции, а не вкус: доказательство завершения локального поиска (§5) стоит
на строгом убывании последовательности в `ℤ≥0`. Свёртка со сравнением
вещественных чисел даёт зацикливание на разнице порядка машинного эпсилон, и
это не гипотеза: свойство Q6 модели перечисляет каждый принятый ход и падает,
если хоть один не уменьшил `Π` строго.

Нормированная величина `Qᵢ(x) = 1 − πᵢ(x)/πᵢᵐᵃˣ ∈ [0,1]` — представление для
человека, а не предмет минимизации. Агрегат `Q(x) = Σ wᵢQᵢ / Σ wᵢ` показывается
одним числом на экране `S-40`.

### 3.3 Вычисляется движком (человек не вводит)

`cap(c) = min(slotsPerDay, σ(par(c)))` (AR-114); `dayLength` в минутах;

### 3.4 Глубина поиска и прогресс (AR-129, AR-130, AR-138)

Человек выбирает **глубину**, а не секунды: одно и то же число секунд означает
разную работу — при жёстких параметрах сетка собирается за доли секунды, при
многих классах и мягких требованиях счёт идёт на минуты. Сегмент «Быстрый ·
Стандартный · Тщательный» задаёт число вариантов мультистарта (5 · 30 · 200) и
число проверок качества; поиск останавливается раньше, если несколько вариантов
подряд не улучшили результат.

Стратегия — мультистарт с локальным спуском: движок собирает несколько
вариантов и берёт лучший. Измерено на первой школе: 20 вариантов дают
`Π = 1022` против `1128` у одиночного прогона — минус 21 % оставшегося зазора
тем же кодом (`40-bench.md`). Точный решатель CP-SAT встанет за тем же
контрактом и заменит мультистарт, не меняя ни одного параметра реестра.

Долгая работа не переживает ни таймаут HTTP-клиента, ни обратный прокси,
поэтому генерация — **асинхронная задача**: `POST /api/v1/schedule/generate`
отдаёт `jobId`, экран `S-42` опрашивает состояние тем же поллингом, что
ожидание скана QR (AR-87).

**Экран генерации — модальное окно с анимацией сборки расписания, без единой
цифры.** Человек по ту сторону не обязан знать слова «перезапуск» и «качество
88 %»; ему нужно видеть, что система работает, и иметь возможность отменить.
Счётчики вариантов и штрафа уходят в аудит и отладку, наружу не выходят.

## 4. Маркеры качества (AR-119)

Каждый маркер задан целым штрафом и явной верхней границей. Верхняя граница
существует не ради красоты: без неё `Qᵢ ∈ [0,1]` не выводится, и «качество 87 %»
превращается в число без области определения.

| Маркер | Штраф `πᵢ` | Верхняя граница `πᵢᵐᵃˣ` |
|---|---|---|
| `prio` | `Σ_{u: prio} max(0, pos(u) − ⌈p/2⌉)` | `|U_prio| · (p − ⌈p/2⌉)` |
| `dayBalance` | `Σ_c Σ_δ |n_{c,δ}·d − H_c|` | `Σ_c maxSpread(H_c, d, cap(c))` |
| `subjectSpread` | `Σ_{c,j,δ} max(0, m_{c,j,δ} − 1)` | `Σ_{c,j} (h_{c,j} − 1)` |
| `teacherBalance` | `Σ_t Σ_δ |n_{t,δ}·d − H_t|` | `Σ_t maxSpread(H_t, d, p)` |
| `groupEdge` | число групповых часов не первым и не последним уроком дня | число групповых часов |
| `stability` | число часов, сместившихся против подтверждённой сетки | размер подтверждённой сетки |
| `firstLast` | число приоритетных часов последним уроком дня | `|U_prio|` |

`maxSpread(H, d, cap)` — точный максимум суммы `Σ|n_δ·d − H|` при `Σ n_δ = H`
и `n_δ ≤ cap`, достигаемый набиванием дней под потолок. Функция вычисляется
явно, а не берётся оценкой сверху: свойство Q4 модели сверяет её результат с
перебором **всех** разбиений малой задачи и падает при расхождении.

### 4.1 Нижняя граница и потолок качества (AR-128)

Рядом с каждым штрафом слой считает **нижнюю границу** `πᵢᴸᴮ` — величину, ниже
которой не опускается никакая расстановка при данной нагрузке. Она следует из
арифметики, а не из удачи перебора:

| Маркер | Нижняя граница | Откуда |
|---|---|---|
| `dayBalance`, `teacherBalance` | `2·r·(d−r)`, где `r = H mod d` | самое ровное распределение `H` часов по `d` дням |
| `subjectSpread` | `Σ max(0, h_{c,j} − d)` | часов предмета больше, чем дней: сгущение неизбежно |
| `prio` | излишек приоритетных часов над ранними позициями недели, разложенный по ближайшим поздним | ёмкость первой половины дня конечна |
| `firstLast` | `max(0, min(d, H_c) − неприоритетные часы класса)` | последние уроки дней нечем закрыть, кроме приоритетных |
| `teacherGap`, `groupEdge`, `stability` | 0 | ноль достижим в принципе; объявить границу выше значило бы занизить требование к слою |

Потолок качества `Q_LB = Σ wᵢ(1 − πᵢᴸᴮ/πᵢᵐᵃˣ) / Σ wᵢ` показывается **рядом** с
агрегатом: «88 % при пределе 97 %» — суждение, «88 %» — число без шкалы. Граница
не обязана быть достижимой: ограничения взаимодействуют, и настоящий минимум
лежит между ней и найденным локальным. Поэтому она называется границей, а не
эталоном, и выдавать её за достижимую цель запрещено.

Маркер `stability` активен только при наличии подтверждённой сетки. Он и есть
ответ на вопрос «почему регенерация не должна перетряхивать школу»: прогон Q10
модели показал, что регенерация с другим зерном сдвигает 108 часов из 112 —
то есть без веса на стабильность школа получает новое расписание целиком там,
где просила поправить один предмет.

## 5. Автопроверка (AR-120)

Инварианты `I-1…I-8` — машинная форма ограничений H1…H7 плюс проверка границ.
Движок применяет их в четырёх точках: после генерации, после каждого хода
автокорректировки, до применения ручного хода, до публикации снимка.

| Инвариант | Что утверждает | Соответствие |
|---|---|---|
| `I-1` | каждая единица размещена ровно один раз, посторонних размещений нет | H1 |
| `I-2` | педагог не занимает два слота одновременно | H2 |
| `I-3` | класс не занимает два слота одновременно | H3 |
| `I-4` | у групповой единицы по одной части на группу, части «весь класс» в ней нет | H4 |
| `I-5` | занятые позиции дня класса образуют префикс `1…k` | H5 |
| `I-6` | `k` не выше дневного потолка параллели | H6 |
| `I-7` | координаты слота лежат в `D × P` | границы |
| `I-8` | длина дня не выше 420 мин | H7 |

Правило применения: **нарушение жёсткого инварианта — дефект движка, а не ввода
человека.** Такая сетка наружу не выходит ни в каком виде; API отвечает
`INVARIANT_BROKEN` с адресом нарушения (класс, день, позиция) и номером
инварианта, движок пишет в аудит зерно и параметры. Показать человеку сетку,
про которую известно, что она нарушает норму, — худший из исходов: школа
поставит её в работу, а обнаружит это надзор.

Полнота набора доказывается не рассуждением: свойство Q2 модели подделывает
сетку пятью разными способами и требует, чтобы каждая подделка была поймана
именно тем инвариантом, который ей отвечает.

## 6. Автокорректировка (AR-121)

### 6.1 Окрестность

`N(x)` — замкнутый список ходов, названный явно:

- `MOVE(u → δ)` — перенос единицы `u` в первую свободную позицию её класса в
  дне `δ`. Других позиций не перебирается: по H5 занятые позиции дня образуют
  префикс, поэтому единственная позиция, куда единица встаёт в чужой день, —
  следующая за концом префикса.
- `SWAP(u₁, u₂)` — обмен позициями двух единиц **одного** класса. Обмен между
  классами в окрестность не входит: он рвёт префикс сразу у обоих, а межклассовый
  перенос уже покрыт ходом `MOVE`.

`|N(x)| = |U|·d + Σ_c C(H_c, 2)`. На первой школе это 1288 ходов на один шаг
поиска — величина названа числом, а не словом «перебор соседей».

### 6.2 Правило приёма и завершение

Движок принимает ход, когда результат (а) допустим по `I-1…I-8` и (б) строго
уменьшает `Π`. Отсюда завершение:

> Последовательность `Π(x₀) > Π(x₁) > …` лежит в `ℤ≥0` и строго убывает,
> следовательно обрывается не позже чем через `Π(x₀)` шагов. Поиск
> останавливается в локальном минимуме `N`, а не по таймеру.

Таймер (5 секунд либо 2000 ходов, `[дефолт]`) остаётся, но его роль — потолок
ожидания человека, не гарантия остановки. Разница существенна: без строгого
убывания таймер прячет зацикливание вместо того, чтобы его исключить.

Автокорректировка **детерминирована**: ходы перебираются в фиксированном
порядке, при равенстве `Π` побеждает первый. Два прогона на одном входе дают
одну сетку (свойство Q7) — иначе жалоба «после исправления стало хуже»
невоспроизводима.

### 6.3 Размен между маркерами показывается всегда (AR-128)

Скалярная свёртка обязана разменивать: уменьшая `Π` на `5·Δ` по весомому
маркеру, она платит `2·δ` по лёгкому. Это её правильное поведение, а не дефект.
Дефектом это становится в момент, когда размен не показан: человек читает
«качество выросло», а в его школе приоритетный предмет стал последним уроком
вдвое чаще. Прогон на первой школе такой размен даёт — `firstLast` растёт с 11
до 14 при падении `Π` с 2080 до 1128.

Поэтому автокорректировка возвращает список ухудшившихся маркеров (`traded`) с
величинами «до → после», а `S-42` печатает его рядом с итогом. Скрыть размен за
агрегатом — то же самое, что показать среднюю температуру по больнице.

### 6.4 Что автокорректировка не делает

Она не переступает жёсткий инвариант ради мягкого маркера и не принимает
ухудшающий ход. Механизмы, которые ухудшают ради выхода из локального минимума
(отжиг, табу-поиск), в блок не входят [слот]: их цена — потеря детерминизма,
а выигрыш на задаче размера первой школы не измерен.

## 7. Ручная корректировка (AR-122)

Человек двигает уроки тем же ходом, что и машина. Различие не в множестве
ходов, а в праве принять ход, ухудшающий мягкий маркер.

| Ход человека | Что делает движок |
|---|---|
| Ход нарушает `I-1…I-8` | отказ `MOVE_REJECTED` с номером инварианта и адресом; ход не применяется никогда |
| Ход уменьшает либо сохраняет `Π` | применяется сразу |
| Ход увеличивает `Π` | ответ `MOVE_DEGRADES` с разбором: какой маркер и на сколько; повтор запроса с `confirm: true` применяет ход и ставит на слот признак `manual` |

Признак `manual` держится на слоте до следующей полной генерации и означает
одно: автокорректировка этот слот не трогает. Без такого признака человек
двигает урок, а машина возвращает его назад следующим прогоном — и школа
считает, что интерфейс её обманул.

**Обратимость (AR-90).** У каждого хода есть обратный: `MOVE` обращается
`MOVE` в прежнюю позицию, `SWAP` самообратен. Журнал ходов сетки хранит
последовательность, кнопка «отменить» применяет обратный ход последнего.
Свойство Q9 модели перечисляет оба вида хода и требует возврата сетки в
исходное состояние.

**Гейт материализации.** Ручной ход над подтверждённой сеткой меняет шаблон и
запускает ту же переработку уроков, что регенерация: урок с отметками
отвязывается, урок без отметок исчезает (AR-85, ворота G-42). Отметка не
удаляется правкой расписания ни при каком ходе.

### 7.1 Годовая норма не нарушается сборкой, а час не теряется (AR-144…AR-146)

Ручная правка — **единственный** источник расхождения с учебным планом. После
автоматической сборки такого расхождения не бывает по построению: годовой объём
входит в арифметические отказы до перебора и в инвариант `I-2` после, поэтому
сообщение «за год выйдет N часов вместо M» существует только с явной пометкой
«после правки вручную» (`PLAN_DIVERGES_BY_HAND`). Признак
`PLAN_IS_LAW_FOR_GENERATION` в контракте поднят, ворота G-63 проверяют оба
утверждения.

Когда час всё-таки не проведён — праздником, правкой завуча или снятым предметом
— движок не переставляет соседей и не сообщает о потере. Счёт один на все три
причины:

```
долг = положено по плану на дату − проведено на дату
```

Отрицательное значение — забег вперёд, ноль — ровный счёт, положительное —
недобор, и на него движок отвечает **адресным предложением**: предмет, класс,
дата, номер урока следующей недели (`MAKE_UP_OFFERED`). Слот подбирается тем же
поиском и под теми же жёсткими ограничениями `H1…H7`; если следующая неделя
заполнена до потолка, движок говорит именно это (`MAKE_UP_NO_ROOM`), а не молчит.

Уход педагога из тенанта школы переводит сетку в **режим подстраховки** на
четыре недели: предмет снимается, освободившиеся позиции заполняются остальными
предметами класса тем же перебором, что и полная сборка (окон у класса не
возникает, `I-5` держится),
недобор копится в счёте с причиной `teacher-left`, а в кабинете завуча висит
остаток срока (`COVER_MODE_ON`). По истечении срока движок называет накопленный
недобор в часах и предъявляет школе выбор — назначить педагога либо изменить
учебный план (`COVER_MODE_EXPIRED`), — но **ни плана не правит, ни предмета из
него не удаляет**: оба действия принадлежат кабинету завуча.

Механика целиком, с текстами и структурами, — [`35-parameters.md` §7.5](./35-parameters.md).

## 8. Графическая маркировка (AR-123)

Маркировка — слой поверх сетки, а не раскраска ячеек. Слои независимы и
включаются раздельно; легенда конечна и перечислена здесь целиком.

| Слой | Что показывает | Форма |
|---|---|---|
| Базовый | предмет, педагог, группа | текст ячейки; групповой час — ячейка, делённая по диагонали (`S-40.cell.paired`) |
| Качество | вклад ячейки в штраф | подчёркивание цветом маркера + иконка + текст в подсказке |
| Происхождение | как ячейка получила своё место | метка `авто` / `правка` / `рука` в углу ячейки |
| Состояние | отношение ячейки к материализации | штриховка для `stale`, перечёркивание для отвязанного урока |

Правило доступности: **цвет не является единственным носителем смысла.** Каждый
маркер несёт иконку и текст; сетка, распечатанная в оттенках серого, читается
без потери информации. Палитра берётся из `docs/design/tokens.json`, контраст
доказывается существующими воротами G-37.

Панель качества на `S-40`: агрегат `Q` одним числом, под ним семь строк
«маркер — значение — сколько ячеек виновны», нажатие строки подсвечивает эти
ячейки в сетке. Панель не советует, что делать: она называет цену.

## 9. Операционные возможности (AR-124…AR-127)

### 9.1 Снимок как единственный источник (AR-124)

Печать, файл и ссылка — проекции **одного** снимка `ScheduleSnapshot`, а не три
независимые сборки. Снимок иммутабелен и несёт: `id`, `workspaceId`,
`templateId`, `version`, `generatedAt`, параметры дня, список слотов.

Причина в арбитре: если распечатка, файл и присланная родителю ссылка собраны
тремя путями, школа не сможет доказать, что было в расписании в четверг.
Свойство Q11 модели перечисляет ячейки печатной и календарной проекций и
требует их совпадения со снимком.

### 9.2 Форматы (AR-126)

| Выход | Формат | Владелец формата | Область |
|---|---|---|---|
| Печать | HTML + CSS `@media print`, A4 альбомная | веб | одна страница на класс либо на педагога |
| Файл-таблица | CSV, UTF-8 с BOM, разделитель `;` | API | сетка класса либо педагога |
| Файл-календарь | ICS (iCalendar): `VEVENT` + `RRULE` недельного повтора, `EXDATE` — нерабочие дни из календаря (AR-100) | API | сетка класса либо педагога |
| Ссылка | подписанный https-адрес снимка | API | класс, педагог либо школа |
| QR | транспорт той же ссылки | веб | тот же |

PDF версия не отрисовывает: печать идёт через диалог браузера, который выдаёт
PDF сам. Серверная отрисовка — слот; её цена (шрифты, кириллица, вёрстка на
сервере) не оплачена ни одним требованием блока.

### 9.3 Ссылка и QR (AR-125, AR-127)

Адрес: `https://<домен>/s/<snapshotId>.<sig>`, где `sig = HMAC-SHA256(secret,
canonical(snapshot) + scope + expiresAt)`. Правила:

1. **QR — транспорт ссылки, а не формат данных.** В код кладётся URL, не сетка.
   Сетка в QR не помещается и, что важнее, не отзывается: розданный по школе
   бумажный код с данными внутри живёт вечно.
2. **Срок и отзыв.** Ссылка живёт 90 дней `[дефолт]` либо до отзыва кнопкой на
   `S-44`; отозванная отвечает `SHARE_REVOKED`, просроченная — `SHARE_EXPIRED`.
3. **Версия сетки входит в подпись.** Публикация новой версии обрывает старую
   ссылку сама: она отвечает `SHARE_VERSION_STALE` и предлагает запросить
   актуальную у школы. Ссылка, молча показывающая прошлогоднее расписание, —
   худший исход, чем ссылка, честно сказавшая «устарела».
4. **Область ссылки перечислена.** `class` — сетка одного класса, `teacher` —
   одного педагога, `school` — вся школа. Ссылка области `teacher` не выдаёт
   сетку других педагогов.
5. **Персональных данных учеников в снимке нет по построению**: слот занимает
   класс либо группа, ученик в сетке не фигурирует (модель данных 1.1.1). ФИО
   педагога в снимке присутствует — это условие читаемости расписания, и право
   на публикацию даёт роль модератора школы (`schedule.share`), а не анонимный
   доступ.

Страница снимка `/s/:token` — публичная, без сессии, только чтение; она не
раскрывает ни одного маршрута приложения и не принимает мутаций.

## 10. FSM: сетка и снимок

Состояния шаблона расширены правкой; состояния снимка вводятся спекой.

### 10.1 Матрица полноты — шаблон сетки

| Состояние | Что сделано | Выход вперёд | Возврат | Дом-экран | Терминал |
|---|---|---|---|---|---|
| `draft` | генератор построил допустимую сетку | автокорректировка либо подтверждение | регенерация с другим зерном | `S-42` | не терминал |
| `repaired` | локальный поиск дошёл до локального минимума | подтверждение | регенерация | `S-42` | не терминал |
| `edited` | человек применил хотя бы один ход | подтверждение | отмена хода, возврат к `repaired` | `S-43` | не терминал |
| `confirmed` | сетка подтверждена, уроки материализованы | публикация снимка | правка ходом переводит в `edited` | `S-40` | терминал построения |
| `stale` | пройденный шаг изменён после подтверждения | регенерация | продолжить правки | `S-40` | не терминал |

### 10.2 Матрица полноты — снимок

| Состояние | Что сделано | Выход вперёд | Возврат | Дом-экран | Терминал |
|---|---|---|---|---|---|
| `none` | снимка нет | публикация со страницы выдачи | начальное состояние, возврата нет | `S-44` | не терминал |
| `published` | снимок выдан, ссылка подписана | отзыв ссылки | перевыпуск с новым сроком | `S-44` | не терминал |
| `superseded` | опубликована новая версия сетки | отзыв старой ссылки | публикация новой версии | `S-44` | не терминал |
| `revoked` | ссылка отозвана человеком | публикация заново | новая публикация выпускает новый адрес | `S-44` | терминал жизни ссылки |

Переход `published → superseded` движок делает сам при подтверждении новой
версии сетки: снимок не может пережить сетку, которую показывает.

## 11. Контракты

### 11.1 Мутации и права

| Мутация | Право | Событие |
|---|---|---|
| `POST /api/v1/schedule/repair` | `schedule.build` | `schedule.template.repaired.v1` |
| `POST /api/v1/schedule/move` | `schedule.build` | `schedule.slot.moved.v1` |
| `POST /api/v1/schedule/move/undo` | `schedule.build` | `schedule.slot.moved.v1` |
| `POST /api/v1/schedule/snapshot` | `schedule.share` | `schedule.snapshot.published.v1` |
| `POST /api/v1/schedule/snapshot/:id/revoke` | `schedule.share` | `schedule.share.revoked.v1` |

| Чтение | Право |
|---|---|
| `GET /api/v1/schedule/quality` | `schedule.read` |
| `GET /api/v1/schedule/export?format=csv|ics&scope=class|teacher&id=…` | `schedule.read` |
| `GET /s/:token` | нет: публичная страница снимка |

Право `schedule.share` заводится этой спекой и добавляется в каталог прав тем же
коммитом (AR-35, ворота G-10). Оно отделено от `schedule.build` намеренно:
построить сетку и вынести её за пределы школы — разные по последствиям действия,
и совмещать их в одном коде значит выдать право на публикацию всякому, кто
двигает уроки.

### 11.2 События (канон AR-23, публичный контракт AR-52)

| Событие | Полезная нагрузка | Подписчик и реакция |
|---|---|---|
| `schedule.template.repaired.v1` | `templateId`, `movesApplied`, `penaltyBefore`, `penaltyAfter` | аудит: запись прогона с зерном |
| `schedule.slot.moved.v1` | `templateId`, `unitId`, `from`, `to`, `actorId`, `degraded` | аудит; журнал — при подтверждённой сетке через ту же переработку уроков, что регенерация |
| `schedule.snapshot.published.v1` | `snapshotId`, `version`, `scope`, `expiresAt` | аудит: факт выдачи данных наружу |
| `schedule.share.revoked.v1` | `snapshotId`, `actorId`, `reason` | аудит |

Каждое событие имеет названного подписчика — событие без подписчика в этот
контракт не входит (найдено генеральным аудитом 1.1.1, AR-108).

### 11.3 Коды отказов

| Код | Когда | Что видит человек |
|---|---|---|
| `INVARIANT_BROKEN` | автопроверка нашла нарушение `I-1…I-8` | номер инварианта, адрес ячейки, предложение регенерации |
| `MOVE_REJECTED` | ручной ход нарушает жёсткий инвариант | номер инварианта, адрес, имя нормы, если инвариант правовой |
| `MOVE_DEGRADES` | ручной ход ухудшает `Π` | маркер, величина ухудшения, кнопка «применить всё равно» |
| `SNAPSHOT_NOT_FOUND` | адрес снимка не существует | текст без раскрытия существования школы |
| `SHARE_EXPIRED` | срок ссылки истёк | дата истечения, просьба запросить новую |
| `SHARE_REVOKED` | ссылка отозвана | тот же текст, что при истечении — снаружи причины неразличимы |
| `SHARE_VERSION_STALE` | опубликована новая версия сетки | «расписание изменилось, запросите новую ссылку» |
| `EXPORT_FORMAT_UNSUPPORTED` | запрошен формат вне перечня §9.2 | список поддержанных форматов |
| `PLAN_DIVERGES_BY_HAND` | **только** после ручной правки годовой объём разошёлся с планом | предмет, класс, сколько выйдет за год против плана, с указанием причины — правка рукой |
| `MAKE_UP_OFFERED` | час не проведён (праздник, правка, снятый предмет) | предмет, класс, причина, дата и номер урока следующей недели с вопросом «добавить?» |
| `MAKE_UP_NO_ROOM` | добрать час на следующей неделе некуда | предмет, класс и прямая причина: все дни заполнены до потолка |
| `COVER_MODE_ON` | аккаунт педагога убран из тенанта школы | класс, снятый предмет, кто вёл, остаток срока подстраховки |
| `COVER_MODE_EXPIRED` | четыре недели подстраховки истекли | класс, предмет, накопленный недобор в часах, выбор: назначить педагога либо изменить учебный план |

`SHARE_EXPIRED` и `SHARE_REVOKED` отвечают одинаково по форме и времени:
различить снаружи, отозвали ссылку или она истекла, нельзя.
