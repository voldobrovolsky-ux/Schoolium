## 2. Находки

### Д1 · Ворота G-53 не выполняют собственный критерий приёмки — «отметка в журнале» 🔴

Ворота этапа 2 в `80-code-prompt.md` названы так: «Chromium-смок проходит полный
онбординг пустой школы — … четверти, нагрузка, генерация, подтверждение,
**отметка в журнале**». Отчёт этапа 2 повторяет это как главный результат:
«пустая школа доводится до подтверждённой сетки и **живого журнала** в браузере».

Смок зелёный и отметок не ставит. После чистого прогона:

```
select count(*) from "Mark";        →  0
select count(*) from "LessonTopic"; →  0
```

Причина не в дефекте журнала, а в календаре. Смок поднимает пустую школу
«сегодня», учебный год начинается 1 сентября, и все материализованные уроки
оказываются впереди:

```
select min(date), max(date), count(*) from "SchoolLesson";
 2026-09-01 | 2026-09-21 | 12          (прогон 2026-08-21)
```

Сервер считает `future: isoDay(c.date) > today()`
(`apps/api/src/schoolium/journal/journal.service.ts:68`), а `openMark` на будущем
уроке показывает тост `LESSON_NOT_HELD` и слой не открывает
(`apps/web/src/schoolium/screens/journal.tsx:197`). То же у шапки даты и `S-51`.
Значит в мире смока **ни одна ячейка журнала не кликается**, и два экрана из
двадцати трёх — `S-51` и `S-52` — не рендерятся ни разу ни одной живой проверкой.

Экранов с живым утверждением в G-53: **20 из 23**. Без единого — `S-51`, `S-52`
(не открываются вовсе) и `S-70` (страница открывается и снимается скриншотом,
но `waitForSelector` принимает любой из трёх идентификаторов, а `has()` по имени
не зовётся ни разу).

**Сам путь при этом рабочий** — и это важно для оценки: дефект в воротах, а не в
продукте. Зонд `e2e/probe-mark-path.mjs` снимает ровно одно отличие (сдвигает
даты колонок журнала в прошлое после старта API) и повторяет тот же путь руками:

```
· колонок «будущий урок» после сдвига дат: 0
✅ клик по ячейке открывает поповер S-52
✅ шесть чипов в порядке 5 4 3 2 н б (AR-79)
✅ кнопка «Убрать отметку» есть
✅ отметка 5 отрисована в ячейке
✅ S-50.col.average пересчитан (AR-115): 5.00
✅ отметка пережила перезагрузку — записана на сервере
✅ клик по шапке даты открывает поповер S-51
✅ тема урока сохранена на сервере
✅ зонд UI-пути отметки: нарушений 0
```

Что закрыть: смоку нужен урок в прошлом. Дешёвый способ — вести смок от даты
внутри учебного года (замороженные часы либо четверти, начинающиеся до
«сегодня»), а не от календарного дня прогона.

### Д5 · G-53 зависит от календарного дня прогона 🟡

Всё из Д1 — следствие одного свойства ворот: путь, который проходит смок,
определяется тем, какое сегодня число относительно 1 сентября. Тот же коммит,
запущенный в сентябре, пойдёт по другой ветке: ячейки станут кликаемыми, `S-52`
откроется, покрытие вырастет само собой. Ворота, у которых объём проверенного
молча меняется с календарём, не годятся в критерий приёмки: зелёный цвет в
августе и в сентябре означает разное. Часы смока нужно зафиксировать —
как уже зафиксировано зерно генератора через `GEN_SEED`.

### Д8 · G-CHECKS.md ссылается на неверный раздел 🟢

Описание G-52: «каждый `data-testid` из **§10** `70-screens.md`». §10 этого файла

сегментов имени (`S-NN.слово.слово`) и молча теряет двухсегментные — `S-10.empty`,
`S-11.preview`, `S-50.table`, `S-60.nav` и им подобные. Считать реестр надо по
второму; первую цифру стоит либо привести к тому же разбору, либо не называть
элементами реестра.

### Д9 · Дрейф цифры утверждений 🟢

### Д10 · Смоки занимают фиксированные порты и не проверяют, что они свободны 🟢

`smoke-onboarding.mjs` и `smoke-textbook.mjs` поднимают API на 3000 и веб на 5173,
а `waitHttp` считает порт готовым, как только по нему кто-то ответил. Осиротевший
процесс предыдущего прогона молча превращает ворота в проверку чужого сервера.
На этой машине так и вышло: G-9 упал с `AUTH_MODE ≠ pilot-qr`, потому что на 3000
ещё висел API прошлого смока, поднятый с `AUTH_MODE=production`. После снятия
процессов ворота зелёные. Обратный случай опаснее: тот же механизм способен дать
ложный зелёный. Нужна проверка занятости порта перед стартом.

## 3. Что проверено и подтвердилось

Помимо перезапуска ворот сверил выборочно то, что отчёты называют решениями:

- **AR-114** (потолок уроков по параллелям) — не декларация: `DAY_SLOTS_CAP`,
  `classDayCap`, `schoolDayCap` в `packages/shared/src/schoolium.ts:191`,
  и генератор считает дневной потолок поклассно (`generator.ts:275`).
- **AR-115** (средний балл — колонка) — `S-50.col.average` в DOM, расчёт по
  числовым, `—` при отсутствии числовых (`journal.service.ts:83`); зонд из Д1
  показал живой пересчёт до `5.00`.
- **AR-113** — коды `STUDENT_HAS_MARKS` и `STAFF_HAS_HISTORY` заведены,
  кодов ровно 29, тексты на месте, статусы 409.
- **AR-69** (кнопка вне роли не рендерится) — правило действительно в библиотеке
  `ui.tsx`, а не в дисциплине экранов.
- **AR-82** — уровень вложенности модалки типизирован (`level?: 1 | 2`), третий
  уровень не выразим.
- **Граница двух контуров** — правило одно и в одном месте (`main.tsx`),
  `GET /api/v1/me` отвечает только сессии 1.1.1 (`access.controller.ts:160`).
- **Ловушка фокуса и возврат фокуса** — реализованы и в `Modal`, и в `Popover`.
- **G-9 не сломан этапом 2** — вытесняемый контур КТП/КПП проходит смок целиком.

**Этап 1 — принят.** Все заявленные ворота воспроизводятся на чистой базе;
расхождение только в цифре 401/409/411, и оно в большую сторону.

написаны и зелёные, найденные по ходу дефекты закрыты. Но:

1. критерий приёмки этапа («отметка в журнале») воротами не достигался, и два
   экрана из двадцати трёх не рендерились ни одной живой проверкой (Д1, Д3);
2. инвентарь `90-master.md` §3, который сам промпт объявил условием сдачи,
   после этапа не был пройден (Д2).

**Обе правки сделаны тем же днём** (§4a), интерфейс переписывать не пришлось.

## 5. Как воспроизвести диагностику

```bash
npm ci
npm run method:lint
npm --workspace apps/api run schoolium:check      # ожидается pass=411 fail=0
npm --workspace apps/api run tenant:check
npm --workspace apps/api run authz:check
node specs/school-onboarding/model/walk.mjs
node specs/school-onboarding/model/props.mjs
npm --workspace apps/web run smoke:onboarding     # 38 шагов
node e2e/smoke-textbook.mjs                       # G-9

# Д1: после зелёного G-53 в базе смока ноль отметок и ноль тем
psql "$SMOKE_DATABASE_URL" -c 'select count(*) from "Mark";'
psql "$SMOKE_DATABASE_URL" -c 'select count(*) from "LessonTopic";'

# Д1: тот же путь с уроком в прошлом — зонд (портит базу, только отладочная)
PROBE_DATABASE_URL=… node e2e/probe-mark-path.mjs
```

Смокам нужен живой Postgres и `CHROMIUM_PATH`, если браузер Playwright лежит не
там, где его ждёт установленная версия. Перед прогоном стоит убедиться, что
порты 3000 и 5173 свободны (Д10).
