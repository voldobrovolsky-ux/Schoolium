# С4а · Адаптивная спецификация: оболочка, модалки, кнопки, состояния

> Дополняет `70-screens.md` (что на экранах) и `60-design.md` (как выглядит).
> Здесь — **как это живёт в двух раскладках**: навигационная оболочка, полный
> реестр модалок, полный реестр кнопок, матрица состояний компонентов.
> Решения: AR-77 (паттерн карточек), AR-80 (гамма), AR-81 (оболочка),
> AR-82 (модалки). Ворота: G-38, G-39.
>
> **Правило номер один:** мобайл — не обрезанный десктоп. Это две раскладки
> одной модели данных. Скрытие элемента на мобайле допустимо, только если оно
> названо в этом документе; молчаливое «не поместилось» — дефект.

## 1. Точки останова

| Раскладка | Ширина | Что меняется |
|---|---|---|
| `mobile` | < 768px | хедер + нижний таб-бар, модалки полноэкранные или нижние листы, одна колонка |
| `desktop` | ≥ 768px | левый сайдбар + топбар, модалки по центру, многоколоночные сетки |

Промежуточной (планшетной) раскладки в 1.1.1 **нет**: планшет получает
десктопную оболочку с сеткой в 2 колонки. Ширина контента десктопа — до 1200px,
дальше поля растут симметрично.

## 2. Навигационная оболочка (AR-81)

### 2.1 Десктоп: сайдбар + топбар

```
┌──────────┬────────────────────────────────────────────────┐
│ SIDEBAR  │ TOPBAR  (64px)                                 │
│ (240px)  ├────────────────────────────────────────────────┤
│          │                                                │
│ логотип  │  CONTENT (max 1200px, паддинг 32)              │
│ ───────  │                                                │
│ Классы   │                                                │
│ Предметы │                                                │
│ Персонал │                                                │
│ Расписан.│                                                │
│ Журнал   │                                                │
│ ───────  │                                                │
│ Кабинет  │  ← только модератор                            │
│          │                                                │
│ [ user ] │  ← низ сайдбара                                │
└──────────┴────────────────────────────────────────────────┘
```

| Элемент | Идентификатор | Поведение |
|---|---|---|
| Сайдбар | `L.sidebar` | контейнер 240px; свёрнутый — 72px, состояние читается атрибутом, а не классом |
| Логотип | `L.sidebar.logo` | ведёт на стартовый экран роли |
| Пункт навигации | `L.sidebar.item.<screen>` | иконка + подпись; активный — заливка `violet-100`, текст `violet-700`, слева полоса 3px `violet-700` |
| Раздел «Кабинет» | `L.sidebar.item.admin` | **виден только роли `moderator`**; не «серый и некликабельный», а отсутствует |
| Карточка пользователя | `L.sidebar.user` | аватар, ФИО, бейджи ролей; клик — меню «Выйти» |
| Кнопка сворачивания | `L.sidebar.collapse` | переключает 240px ↔ 72px (только иконки, подписи в tooltip); выбор хранится локально |
| Заголовок экрана | `L.topbar.title` | название текущего экрана |
| Хлебные крошки | `L.topbar.breadcrumb` | появляются только внутри класса и предмета: «Классы / 5А» |
| Кнопка сканера | `L.topbar.scan` | иконка QR; **видна ролям, кроме `moderator`** (модератор показывает коды, а не сканирует) → `S-70` |

Сайдбар **не скрывается** при открытии модалки — он уходит под блюр вместе с
контентом. Скролл — только в контентной области; сайдбар и топбар зафиксированы.

### 2.2 Мобайл: хедер + таб-бар

```
┌────────────────────────────────┐
│ HEADER (56px)                  │  заголовок · [кабинет] · [скан]
├────────────────────────────────┤
│                                │
│  CONTENT (одна колонка,        │
│  паддинг 16, скролл)           │
│                                │
├────────────────────────────────┤
│ TABBAR (64px + safe-area)      │  5 вкладок
└────────────────────────────────┘
```

| Элемент | Идентификатор | Поведение |
|---|---|---|
| Заголовок | `L.header.title` | название экрана; внутри класса — «‹ 5А» с возвратом |
| Кнопка «Кабинет» | `L.header.admin` | иконка; **только у `moderator`** |
| Кнопка сканера | `L.header.scan` | иконка QR; у всех, кроме `moderator` |
| Карточка пользователя | `L.header.user` | аватар; клик — `M-15` нижним листом |
| Таб-бар | `L.tabbar` | пять вкладок в фиксированном порядке: **Классы · Предметы · Персонал · Расписание · Журнал** |
| Вкладка | `L.tabbar.item.<screen>` | иконка + подпись 11px; активная — иконка и подпись `violet-700` |

**Кабинет модератора не является шестой вкладкой** — пять вкладок одинаковы для
всех шести ролей, различие ролей выражается доступностью действий внутри
экранов (AR-69), а не разной навигацией. Иначе два человека, обсуждая продукт по
телефону, видят разные меню.

Таб-бар **скрывается** в полноэкранных модальных потоках (мастера, регистрация,
сканер) и возвращается по их завершении. Нижний отступ контента учитывает
`env(safe-area-inset-bottom)`.

### 2.3 Оболочка вне сессии

Экраны `S-00`, `S-01`, `S-05`, `S-03`, `S-04` показываются **без оболочки**: ни сайдбара,
ни таб-бара, ни хедера. Единственный элемент — логотип. На обеих раскладках это
центрированная карточка: десктоп 420px, мобайл — во всю ширину с паддингом 24.

## 3. Реестр модалок

**Общие правила (AR-82):**
- Открытие: глухое затемнение `overlay-blur` (`rgba(23,16,38,0.60)`, БЕЗ блюра —
  правка владельца 2026-08-30: контент под слоем не читается), контент под
  ним не скроллится (`body` фиксируется), карточка появляется fade+scale 150 мс.
- Закрытие: крестик, `Esc`, клик по фону. **Исключение:** если в мастере введены
  данные — клик по фону и `Esc` показывают подтверждение «Закрыть без
  сохранения?»; крестик ведёт себя так же.
- Фокус: при открытии — на первый интерактивный элемент; ловушка фокуса внутри;
  при закрытии — возврат на элемент-открыватель.
- Вложенность: **максимум два уровня** (карточка → QR-слой). Третий уровень —
  дефект конструкции, а не «так получилось».
- Заголовок каждой модалки — `h2`, доступен скринридеру (`aria-labelledby`).

прилипает к низу над safe-area.

## 4. Реестр кнопок

| ID | Роль в интерфейсе | Внешний вид | Desktop | Mobile |
|---|---|---|---|---|
| `B-primary` | Основное действие экрана | `violet-700`, текст белый, радиус 12 | высота 44, паддинг 0/20, по содержимому | высота 48, **во всю ширину** |
| `B-accent` | Ключевое действие шага (генерация, QR) | `pink-600`, текст белый | высота 44 | высота 48, во всю ширину |
| `B-secondary` | Вторичное действие | белая, рамка `border.default`, текст `violet-700` | высота 44 | высота 48 |
| `B-ghost` | Третьестепенное («Назад», «Отмена») | без рамки, текст `ink.secondary` | высота 44 | высота 48 |
| `B-danger` | Разрушительное («Удалить») | текст `state.danger`, без заливки | высота 44 | высота 48 |
| `B-off` | Явный отказ («⌀ Без литер») | рамка `border.default`; выбранная — заливка `violet-100` | высота 44 | высота 48, во всю ширину |
| `B-icon` | Иконка без подписи (скан, крестик, свернуть) | круг/квадрат 40 | 40×40 | **44×44** |
| `B-fab` | Круглая «+» на карточке предмета | `pink-600`, круг 40 | 40 | 44 |
| `B-chip` | Выбор из набора (группы, приоритеты, отметки) | пилюля, выбранная — `violet-100` | высота 32 | высота 44 |

**Правила размещения:**
- **Одна `B-accent` на экран.** Две розовых кнопки одновременно — дефект (AR-80).
- Пара кнопок: **десктоп** — в ряд справа, primary справа от secondary;
  **мобайл** — колонкой, primary сверху, обе во всю ширину.
- В полноэкранной модалке кнопки прилипают к низу; в обычной — в футере карточки.
- Кнопка, недоступная роли, **не рендерится** (не «disabled с подсказкой»):
  disabled означает «нельзя сейчас», отсутствие — «не ваша роль» (AR-69).
- Ширина кнопки на мобайле — во всю ширину контейнера, кроме `B-icon`, `B-fab`, `B-chip`.

| QR-панель | код активен | — | — | — | — | скелетон 240×240 | «Код погас» + кнопка «Открыть заново» |

**Состояния экрана целиком** (обязательны на каждом из 21):
`loading` — скелетоны блоков той же геометрии, не спиннер по центру;
`empty` — иллюстрация + заголовок + одна кнопка (скрытая у роли без права);
`error` — карточка с причиной и кнопкой «Повторить»;
`forbidden` — для `/admin` у не-модератора: «Раздел доступен модератору школы».

**Тосты:** появляются снизу по центру (мобайл — над таб-баром), живут 4 секунды,
максимум один одновременно, не перекрывают кнопку действия. Используются только
для необратимых уведомлений («Урок ещё не прошёл»), не для подтверждения
успешных сохранений — успех показывается изменением самих данных.

| `S-80` Устройства | список сессий + завершение; кнопка «Подключить» скрыта без камеры | список в одну колонку; «Подключить устройство» открывает камеру во весь экран |

**Железное правило прокрутки:** `body` не скроллится по горизонтали **никогда**.
Широкое содержимое (три таблицы: контингент, расписание, журнал) скроллится
внутри собственного контейнера с `overflow-x: auto`. Проверяется в смоке.

## 7. Ввод на мобайле

| Поле | `inputmode` | Дополнительно |
|---|---|---|
| Телефон | `tel` | маска, автозаполнение `autocomplete="tel"` |
| Код от модератора (`S-05`) | `numeric` | 6 отдельных ячеек |
| Часы, численность, параллели | `numeric` | шаговые кнопки «−»/«+» рядом (44×44) |
| ФИО | `text` | `autocapitalize="words"` |
| Даты четвертей | нативный date-picker | на десктопе — календарь-поповер |

Открытая клавиатура не должна перекрывать активное поле: контейнер модалки
поднимается, прилипшие кнопки остаются доступны.

## 8. Что в адаптации НЕ делаем
Планшетную раскладку · ландшафтную версию мастеров · жесты кроме свайпа вниз на
нижнем листе · выдвижной сайдбар-«бургер» на мобайле (там таб-бар) · разное меню
для разных ролей · тёмную тему.
