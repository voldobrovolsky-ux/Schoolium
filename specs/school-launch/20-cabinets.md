# Кабинеты 1.2.0

**Статус: Accepted** — принят правками владельца 2026-08-28 (редакция 2:
восемь ролей, успеваемость вместо рейтинга). Решения: AR-150, AR-151,
AR-152, AR-158, AR-159, AR-160. Принцип AR-69 сохраняется: экраны общие,
различие ролей — в данных и доступных действиях; закрытый раздел отвечает
403 с причиной, а не исчезает из навигации.

## 1. Роли 1.2.0 (AR-150)

Восемь ролей, роли совместимы (массив, как в 1.1.1). Идентификаторы кода —
текущие; переименование словаря (`head_teacher`, `CEO`…) — после события.

| Роль | Код 1.2.0 | Новая? |
|---|---|---|
| админ школы (полное управление workspace) | `admin` | да — реализует AR-148 |
| модератор школы | `moderator` | есть, права сужаются |
| директор | `director` | есть |
| учредитель (CEO) | `founder` | есть |
| завуч | `deputy_academic` | есть |
| зам. по воспитательной работе | `deputy_upbringing` | есть |
| преподаватель | `teacher` | есть |
| родитель | `parent` | да |
| ученик | `student` | да |

`hostess`, `methodist`, `head_teacher`, `CEO`, `coefficient`, `diary` и
прочие слова словаря владельца — **имена для сущностей, а не задание на

версии не являются и не реализуются; имена зарезервированы на будущее.
Глобальный админ EduStore/Schoolium (владелец) — не роль школы: консольный
контур AR-93, экрана в школе у него нет.

## 3. Совмещения выводятся из фактов, не из ролей (AR-151)

- **«+ профили своих детей»** у любой штатной роли: существует
  `GuardianLink` на ту же учётку → блок «Мои дети» на главной появляется
  автоматически, отдельная роль `parent` не выдаётся.
- **«+ журнал своих предметов — если есть»**: существует `TeacherBinding`
  на эту учётку → в своих уроках доступны отметка и тема, независимо от
  прочих ролей. Проверка принадлежности урока — та же, что у `teacher`.
- Разделение обязанностей по идентичности (AR-61) не ослабляется.

## 4. Дневник (`S-90`, AR-158)

Проекция для `student` и для `parent` (в профиле ребёнка). Ни одной мутации.

- Неделя как школьный дневник: дни → материализованные уроки ребёнка
  (с учётом его группы) → предмет, номер/время слота, тема урока (если
  заполнена), отметка.
- Вид недели — общий с расписанием `S-40` (AR-175, УТЦ v1.4): строка
  «N. Предмет (1|2)» в общей нумерации дня по скелету (AR-171), отметка —
  сразу после названия предмета, времена «HH:MM — HH:MM» из скелета (без
  скелета — из параметров дня). Мобайл — пикер дня (слот неподвижен, лента учебных дней едет под ним), дата только под открытым
  днём; десктоп — лента недель и вся неделя 3+3 (ПН/ВТ/СР | ЧТ/ПТ/СБ).
- Источник — те же проекции, что у журнала (`SchoolLesson`/`Mark`/
  `JournalRow`): дневник не хранит ничего своего (AR-110).
- Колонки ДЗ нет вовсе — появится в инкременте №2, пустая колонка не
  показывается.
- Навигация по неделям — как календарь недель журнала `S-50`; текущая
  неделя открывается автоматически.

Пустые состояния (обязательны, FLOR-ADS §5.21): расписание не подтверждено →
«Расписание ещё не составлено — загляни позже»; уроки есть, отметок нет →
сетка недели без отметок (не выглядит ошибкой); каникулы/нерабочий день →
день помечен, не пуст.

## 5. Успеваемость (`S-91`, AR-159)

**Средние баллы по каждому предмету** — в профиле ребёнка у родителя и в
кабинете ученика. Правило среднего одно на систему (AR-79, AR-115): числовые
2–5, «н» и «б» не участвуют, числовых нет — «—», а не ноль. Ни одной мутации.

**Рейтинг класса (ранжирование) в 1.2.0 не строится** — спецификация
рейтинга пишется отдельно (решение владельца 2026-08-28); условие введения —
принятая отдельная спека.

## 8. Словарь экранов

**КПЦ** (контингентно-персональный центр) — собирательное имя контура
«Классы/Ученики (`S-10`–`S-13`) + Персонал (`S-30`–`S-32`) + Родители
(`S-14`)». **УТЦ** — календарь + расписание + журнал (AR-149); панель
управления УТЦ = `S-40`–`S-42` + управление предметами. УПЦ не существует
(подтверждено владельцем 2026-08-28: опечатка).

## 9. Недостающие проверки

G-66 (матрица §2 перечислением — расширение G-41/G-10), G-67 (дневник и
успеваемость — проекции без мутаций), G-70 (идемпотентность пресета) —
заведены в `docs/G-CHECKS.md`; условие появления — реализация.

## 10. Разделение кабинетов 1.3.0 (AR-186)

Решение владельца 2026-09-02: кабинеты разделены **по праву, а не по роли**;
человек с двумя ролями видит оба кабинета. Маршрут `/admin` отдан
администратору; кабинет модератора переехал на `/moderator`.

| Кабинет | Маршрут | Экран | Право | Кто |
|---|---|---|---|---|
| администратора | `/admin` | `S-62` | `school.admin` | `admin` |
| модератора | `/moderator` | `S-60` | `school.manage` | `moderator`, `admin` |
| завуча | `/deputy` | `S-61` | `school.oversee` | `deputy_academic`, `admin` |

Новые права версии: `school.admin` (мутационное, только `admin`) и
`school.oversee` (надзорное, отдельная группа `OVERSIGHT_PERMISSIONS` —
не «читающее», потому что пятёрка `*.read` выдаётся всем штатным ролям, а
кабинет завуча — только завучу и администратору). Матрица §2 в части
экранов не меняется; колонка «Устройства (`S-80`)» остаётся личной у каждой
роли, а устройства **всех** людей школы — раздел `S-62`.

Операционная матрица «что администрируется где» × четыре роли, семантика
карты устройств, порядок дистанционной активации и инцидент-режима — в
[docs/CABINETS.md](../../docs/CABINETS.md); это единственное место (П-5),
здесь она не повторяется. Связанные решения: AR-187 (происхождение
сессии), AR-188 (лимиты и инцидент), AR-189 (ссылка входа 48 ч), AR-193
(чек-листы завуча из данных), AR-194 (адрес входа — 90 дней). Ворота:
G-81, G-82.
