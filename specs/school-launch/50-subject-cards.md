# Единая карточка предмета

**Статус: Draft — реализация только после подтверждения владельцем (П-2).**
Источник требования — правка владельца 2026-08-30, дословно: карточки предмета
на каждый класс создавать неправильно; карточка одна, в ней строчки классов с
педагогами; деление на группы — кнопкой, «разделение провоцирует создание
журнала для каждой группы»; «вначале спека, потом чёткое разделение по всей
программе, чтобы был не UI только рабочий, а полноценный механизм».

## 1. Что меняется и что остаётся

| Сейчас (1.2.0) | Становится |
|---|---|
| `SchoolSubject` — запись «предмет × класс»: «Математика 5 класса» и «Математика 6 класса» — две несвязанные карточки | **Предмет** — одна сущность («Математика») со **строками классов**: 3, 4, 5, 6, 7, 8 |
| Деление на группы — свойство КЛАССА (мастер классов, на все предметы разом) | Деление на группы — свойство **строки класса в предмете**: английский в 7-м делится, алгебра в 7-м — нет |
| Привязка педагога — к карточке «предмет × класс», scope класс или группы | Привязка — к строке класса; при делении — к конкретной группе строки |
| Журнал — на «предмет × класс» | Журнал — на строку класса; **при делении — журнал на каждую группу** |

Не меняется: маршрут привязки педагога (QR/скан из личного кабинета — §4),
журнальная механика отметок, дневник (он читает уроки, а урок несёт группу).

## 2. Модель

- `Subject` (workspace-уровень): `id, name`. Имя уникально в школе.
- `SubjectClassRow`: `subjectId, classId, groupCount (0 = без деления | 2…4)`,
  часы в неделю (из штатки, для нагрузки).
- Привязка: `TeacherBinding {rowId, groupNo (0 = вся строка | 1…groupCount), teacherId}`.
  В строке без деления — одно место педагога («по дефолту место на одного»);
  в поделённой — место на каждую группу.
- Журнал: колонки живут на `(rowId, groupNo)` — деление строки СОЗДАЁТ журнал
  каждой группе; отметки существующего журнала при включении деления остаются
  в журнале группы 0 и читаются (архивный слой), новые ставятся в журналы групп.
- Состав групп: **живёт на классе** (`StudentGroup`, как сейчас) — узел N-6
  закрыт [РЕШЕНО] правкой владельца 2026-08-30: «группы идентичны для всех —
  дети 1 группы ходят на первые группы в любом предмете одинаково». Строка
  предмета не хранит свой состав: её деление — это выбор «вести по группам
  класса», и число групп берётся из класса. Табличка количества групп из
  маршрута создания (§3) при первом делении задаёт число групп КЛАССУ (если
  класс ещё не делён), дальше — только переключатель «по группам / целиком».

## 3. Создание карточки (маршрут владельца, дословно)

1. «Создать карточку» → ввод **названия предмета**.
2. Указание **классов** (список чекбоксов из классов школы).
3. Указание классов, **где нужно деление на группы**: классы стоят списком,
   справа переключатель; где переключили — появляется табличка с количеством
   групп, по дефолту 2.
4. «Создать» → карточка создана, строки классов видны сразу (поделённые —
   сразу отображаются поделёнными), можно прикреплять педагогов.

Кнопка деления доступна и ПОСЛЕ создания — на строке класса (правка владельца:
«сделай кнопку разделения на группы»). Обратное слияние групп — отдельное
действие с подтверждением объёма потери (журналы групп закрываются в архив).

## 4. Привязка педагога к строке и группе

Маршрут тот же, что в 1.2.0 (заложено владельцем): педагог подходит, из
личного кабинета (сканер `S-70`) сканирует QR на карточке предмета и
присоединяется. Уточнение адреса:

- QR выпускается **на место**: строка класса (без деления) или группа строки
  (с делением). На карточке у каждого места своя кнопка «Показать QR».
- Скан помечает место «педагог отсканировал»; модератор подтверждает — привязка
  создана. Один педагог может занять несколько мест (Учитель 4: 7 кл 1 гр. и
  8 кл 1 гр. — два скана либо подтверждение модератором без пересканов —
  кнопка «привязать к другим местам» на подтверждении).
- Вакансия (география, химия): место пустое, журнал существует, уроки без
  педагога не материализуются — строка ждёт привязки.

## 5. Миграция с 1.2.0

Существующие «предмет × класс» группируются по имени: N карточек «Математика»
разных классов становятся одной картой с N строками. Привязки и журналы
переезжают на строки 1:1 (`groupNo 0`). Прогон — идемпотентный скрипт с
отчётом; событие 30.08 идёт на механике 1.2.0, миграция — сразу после.

## 6. Права

Карточки предметов ведёт модератор (КПЦ-рутина заведения). Завуч выставляет
**годовую норму по предметам** (правка владельца 2026-08-30: «УТЦ не весь у
завуча, завуч только годовую норму по предметам выставляет») — норма живёт на
строке класса; остальная панель УТЦ (календарь, сетка, генерация) — у
модератора/админа. Отражается правкой `20-cabinets.md` §3 и каталога прав.

## 7. Проверки (П-4)

| Что | Проверка |
|---|---|
| Деление строки создаёт журнал каждой группе | G-71 (новая): поделить строку → перечислить журналы групп, отметка в журнале группы 1 не видна в группе 2 |
| Слияние не теряет отметки | G-71: слить → журналы групп в архиве, отметки читаются |
| Привязка к месту | G-72 (новая): QR места группы 2 не привязывает к группе 1 |
| Миграция 1:1 | G-73 (новая): счётчики привязок/колонок/отметок до и после равны |
| Имя предмета уникально | вход в `Subject.create` |
